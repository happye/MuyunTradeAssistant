## 观察协议冻结候选（K1 验收后定版）

一条候选记录需同时保存：证券、周期、真实已接受计划的 id/revision/content_hash、主意图引用、评估 id/status/snapshot/method_version、账户版本、证据/行情截止、策略 policy_id 与决策表 rule_version、legacy/fusion 双方 action/target_weight/blockers、execution_status/blocked、as_of、输入与输出指纹。MID/LONG 分别判资格、分别计分母，不能一周期合格就把另一周期算入。旧模拟/草稿、缺快照/账户、变更待复核皆为 diagnostic。

同一次输入重放只留一条；计划/账户/证据/行情/决策/执行任一有意义变化都留新记录。同日同证券可以有多条状态变更，但效果评估按预注册的证券×周期×计划与观察窗去相关，不能把高频重复当独立样本。先冻结记录协议与观察窗，再累计真实样本；旧 20 日/30 组合/10 复评只是运营提案，不是统计充分性或个人使用门槛。

用户界面仍给单一下一步及可展开证据；影子诊断只在 `shadow` 报告展示，不进入 legacy 主行动。发布门维持 requested/effective 分离；只有数据资格、观察、独立复验与明确授权全部满足才考虑 `opt_in`，`default` 另需样本外效果证据。

实施任务、验收命令与停止点见 [K0–K4 任务卡](DELIVERY_PLAN.md)。
