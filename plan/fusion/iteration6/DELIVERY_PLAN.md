## M0｜账户事实到最终行动的同源闭环（READY）

**映射**：R03/R05/R09 → G1/G2/G5，T01/T03；修 W1。

**所有权/边界**：account_service/portfolio 读上下文，analysis_service、decision_policy、shadow_diff 及实际消费入口；相关测试/使用提示。保持模块化单体、既有参数/止损逻辑、账本写入协议。

**设计**：在既有账户适配处一次装配请求内上下文，区分 HELD/NONE/UNKNOWN、quantity、合格 weight 或 None、资格原因、账户版本。字段可以复用现有类型，不为卡面名称另建重复存储。数量事实决定持仓；RATIO_ONLY 保留比例判持仓。冲突/未对账明确 UNKNOWN，不能编造数量。一次 la 批次固定账户版本，下一命令重新读，禁止全局长寿命缓存。

**消费者**：策略→最终包→周期策略→影子→摘要/证据/diff/建议均消费同一上下文；扫描/TUI/Web已有路径同步兼容。REDUCE/EXIT 不依赖权重是否已知来推断有无持仓。未知权重不产生精确新增目标；EXIT 目标 0 是动作定义，不伪造 delta。两臂 target 取规范终态，HOLD 不取内部占位 0。

**用户收益**：实际有股不会同时收到“风险需退出”和“无仓等待”；输出明确“持有100股，权重待重估，退出方向保留”。合格估值可显示派生权重及来源，不继续打印旧比例。

**必须通过**：

1. W1 的 100 股/旧比例 0、900 股/旧比例 .1；硬退出/普通减仓/增仓/持有、已知空仓、真未知账户分别验证；未知权重 REDUCE 不能变 WAIT。
2. 隔离 `pos confirm --qty` → 重启 → l/la/chat/today：断言公开回执、最终 DecisionPacket、影子两臂、证据卡和建议；市场/AI可替身，待验适配器不可 mock 掉。
3. 同请求多股同 account_version，读取次数有断言；下一请求看到新成交。旧比例账户原回归不变。
4. 守卫下跑当前 281 目标回归＋新增反例；实施方按项目规定做隔离离线全量，不能只给 helper 绿灯。

**停止/回滚**：真实账/投影冲突不自动修账；先交保守待对账状态。回滚应用读适配，不撤销已确认成交、不降低旧事实资格门。M0 可先在未知权重路径关闭 W1，不等待 M1 补出可用估值。

## M1｜行情来源时间与观察合同（READY）

**映射**：R05/R08 → G1/G6，T03；修 W2。与 M0 可分卡，最后联合验收。

**所有权**：akshare_client/models 行情适配与预取/缓存，账户估值门、shadow 记录及报告、对应测试/告警映射。不得让 live 字段进入回测未来数据路径。

**设计**：价格 effective_at（可带日精度）、source、fetched_at 分离；Baostock 日线保留原行 date；新浪有源时间则解析，无可靠源时点则明确未知；预取/120秒缓存保留原来源元数据。估值日期按交易所时区解释；缺失、未来或不兼容时间不靠墙钟补齐。现阶段继续保守同日窗，不自行放宽容差；这不代表已完成完整 NAV/交易日历资格。

**观察**：补丁后独立协议版本（建议 shadow_v8），旧 v7 留诊断、不追认。价格时间与采集时间显式记录；evidence_cutoff 的评估时点语义写清，不能宣传成所有原文最大发布时间。两臂 action/target/target_state/blockers/execution 使用各自规范包；版本分组明确。信息未知允许记录诊断，不能为凑分母降低资格。

**用户收益**：降级明确“使用上一交易日收盘；当前权重待重估”；shadow 报告能解释为何不入有效比较。

**必须通过**：真实适配函数接离线供应商行，覆盖实时、Baostock旧日、K线独立回退、无源时间、预取命中、120秒缓存、时区/未来时点。W2 旧价格配新NAV保持 None；同日合法组合可算；记录/去重/报告三处用同一资格规则；纯 capture 时间变化不虚增，行情真实变化保留。联合 M0 做一条完整入口链，缺指标降级不伪造技术结果。

**停止/回滚**：拿不到可靠源时间先保持诊断可交，不引入新供应商或联网扩大范围。旧记录原样保留；版本回滚不可把旧 v7 追认为合格。需真实外源小样时先列请求范围与不写账户的验证方案；当前卡可离线完成已知反例。
