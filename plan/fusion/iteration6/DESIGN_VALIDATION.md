## 先调查再选择方案

| 调查 | 独立结果 | 决策 |
|---|---|---|
| 数量→策略→最终包→周期对照 | W1：100 股 / 旧比例 0 / 策略清仓 → 两处 WAIT | M0 收口现有账户读出口，显式携带持仓状态与权重资格 |
| 原始价格行→行情模型→估值 | W2：旧日收盘被打当日抓取时间，错误取得权重资格 | M1 保留来源有效日与抓取日，缺时点保守降级 |
| 日常入口直接重跑研究 | B1：相同材料，仅 as_of +1 秒，MID/LONG revision 1→2 | M2 日常查看与显式刷新分离，不能修改 as_of 散列规则草率“去重” |
| 逐股装配账户 | B2：1/10/30 次调用分别重放账本 1/10/30 次 | M0 引入请求内同一账户上下文，下一请求刷新，不建全局过期缓存 |

B2 只用一条事件的合成账本，30 次约 15ms；这**不是已证实的性能瓶颈**，不据此承诺 p95 提升。请求内快照的首要收益是同版本一致性；后续大账本基线有需要再测，T05 不能由此关闭。

B1 并非固定输入幂等失败：as_of 本来就是时点语义的一部分。选择只读日常视图可避免无材料变化的候选版本频增，同时保持日期跨越、证据到期、方法版本变化的显式复核能力。不要简单按天截断所有时间或从研究散列删除 as_of。

## 原型与反例

[design_contract_probe.py](design_contract_probe.py) / [结果](DESIGN_CONTRACT_RESULTS.json)：**19 场景通过**。

- 持仓 HELD / NONE / UNKNOWN 与权重独立；HELD+未知权重仍可 EXIT/REDUCE，新增风险冻结；已知空仓不做退出；持仓未知的减仓给复核。
- HOLD 无目标变化，不将内部 0 占位映射为 KNOWN 目标。
- 来源时间缺失、旧日价格配当天 NAV、未来时点、无时区时刻拒绝估值；同一实际时刻的不同偏移可比较。
- 请求内 30 次消费同一版本，下一请求才刷新。
- 日常研究视图重复读取已接受版本、提示候选存在，但不改两槽内容。

限制：原型用简化函数证明语义能区分，不导入产品函数冒充修复。日精度行情在产品中应保留精度标签，不能虚构盘中时刻；样例的带时区时刻处理不自动覆盖交易日历/停牌/复权/NAV 净现金的全部资格。

## 既有架构内的调整

不新增平行业务引擎。`AccountService` 提供权威快照，`PortfolioManager` 保持兼容旧比例账户并装配读上下文；`analysis_service` 与 `decision_policy` 消费同一事实；`shadow_diff` 记录规范化结果及来源。UI 不自行重新判持仓。

M2 复用 `ResearchApplicationService` 增加明确的只读查询/视图边界，CLI 做参数与渲染。查询遇旧方法/缺快照/到期只显示待复核，不在查看时默默重新盖章或接受计划。显式 research 保留生成候选的职责。当前只展开这段；首个完整 MID 样板和 LONG 数据消费者在下一依赖窗口细化。

## 实施后的验证要求

M0/M1 产品回归须失败在行为断言上，再修复；W1/W2 保留原始受审结果，新增修复后结果。单元正确、公开入口一致、观察资格三层各自断言。严格隔离全部持久化路径及网络；改 HOME 不能保护仓库相对路径，CPython审计也不能拦截所有原生扩展IO，须隔离或守卫FAISS等边界（本轮披露见R12）。L1 跨模型 Optional 改动在下一实施交付须做离线全量并报告实际统计。
