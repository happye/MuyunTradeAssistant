# 三、方向一：AI输入增强（技术面摘要）

## 3.1 问题定位

当前 `ai_modifier.py` 在调用 AI 分析新闻时，传递的信息结构为：

```python
prompt = f"分析以下新闻对股票{stock_code}的影响：\n{news_text}"
```

AI 只看到新闻文本，不知道当前技术面状态。这导致：
- "减持公告"在上升趋势中可能只是噪音，但 AI 可能判为重大利空
- "业绩预增"在下跌趋势中可能是诱多，但 AI 可能判为利好
- 缺少技术面对照的新闻情绪分析，本质上是不完整的

## 3.2 方案设计

### 3.2.1 技术面摘要结构

在调用 AI 前，自动注入结构化技术面摘要：

```python
tech_context = {

    "stock_name": "立讯精密",

    },
    "price_position": {
        "close": 34.50,
        "ma5": 33.80, "ma10": 32.90, "ma20": 31.50, "ma60": 28.20,
        "above_ma20_pct": 9.5,     # 收盘价高于 MA20 百分比
        "above_ma60_pct": 22.3,    # 收盘价高于 MA60 百分比
```

### 3.2.2 Prompt 改造

```text
你是一个结合技术面背景分析新闻影响的量化助手。

## 当前技术面背景
{tech_context_json}

## 新闻内容
{news_text}

2. 如果技术面与新闻方向一致（如上升趋势+利好新闻），影响放大
```

1. 同一新闻在上升/下跌趋势中给出不同情绪评分
2. `tech_context_awareness=True` 的比例 > 90%
3. AI 分析理由中明确出现"当前处于上升趋势"等表述
4. 真实A股案例：利空新闻在强上升趋势中被降级处理

# 四、方向二：金字塔仓位管理

## 4.1 问题定位

策略库中有多处明确的金字塔仓位管理描述（如第8章、第12章、第45章），但当前代码的仓位计算是线性的：

```python
# 当前 strategy_layer.py 仓位逻辑（简化）
if signal == ENTRY:
    target_ratio = 0.20   # 固定20%试探
elif signal == ADD:
    target_ratio = 0.40   # 固定加到40%
```

问题：
- 没有"试探仓盈利后才加仓"的保护机制
- 没有仓位档位概念（试探/基础/重仓）
- 减仓是固定比例，没有倒金字塔逻辑
- 止损没有根据仓位大小分层

## 4.2 参考来源

| 来源 | 核心思想 | 对本项目的启示 |
|------|---------|---------------|
| Van Tharp《通往财务自由之路》 | 仓位大小由风险决定（R倍数） | 每笔交易风险固定（如总资金1%），仓位=风险/止损幅度 |
| Elder《以交易为生》 | 金字塔加仓：盈利后才加，每次加仓量递减 | 试探→基础→重仓的升级需盈利保护 |
| Daryl Guppy《趋势交易》 | 倒金字塔减仓：先减大头锁定利润 | 止盈先卖大部分，留小部分跟踪 |
| 《海龟交易法则》 | ATR-based position sizing | 波动率越大仓位越小 |
| A股机构实践 | 分批建仓+分批止盈 | 第1批30%、第2批40%、第3批30% |

## 4.3 方案设计

### 4.3.1 仓位档位体系

```
试探仓 (Pilot):    10-15% — 首次入场，止损宽松(8-10%)
基础仓 (Base):     25-30% — 趋势确认+试探仓盈利>3%
重仓 (Full):       40-50% — 强趋势+基础仓盈利>5%

升级条件：
  试探→基础: 持仓盈利>3% + 趋势确认(MA多头排列) + 持有>5天
  基础→重仓: 持仓盈利>5% + 强趋势(MACD零轴上) + 持有>10天

降级条件：
  重仓→基础: 趋势转弱(MA5下穿MA10) 或 回撤>5%
  基础→试探: 趋势破坏(MA10下穿MA20) 或 回撤>8%
```

### 4.3.2 倒金字塔减仓

```python
# 止盈减仓：先减大头
if 浮动盈利 > 10%:
    减仓比例 = 0.40  # 先减40%
elif 浮动盈利 > 20%:
    减仓比例 = 0.30  # 再减30%
    剩余 = 0.30      # 留30%跟踪止盈

# 止损按仓位分层
if position_tier == PILOT:
    stop_loss_pct = 0.10   # 试探仓10%止损
elif position_tier == BASE:
    stop_loss_pct = 0.08   # 基础仓8%止损
elif position_tier == FULL:
    stop_loss_pct = 0.05   # 重仓5%止损（收紧）
```

### 4.3.3 风险预算模型（Van Tharp R倍数法）

```
每笔交易风险 = 总资金 × 1%（固定）
仓位大小 = 每笔交易风险 / (入场价 - 止损价) × 入场价

示例：总资金100万，风险1万，入场价34.5，止损价31.0
  仓位金额 = 10000 / (34.5 - 31.0) × 34.5 = 98,571
  仓位比例 = 98,571 / 1,000,000 = 9.86% → 试探仓
```

## 4.4 验收标准

1. 回测中仓位自然呈现"试探→基础→重仓"三档升级
2. 试探仓亏损时不再加仓
3. 重仓止损比试探仓更紧
4. 止盈先减大头、留小部分跟踪
5. 与 v0.8.2 交易语义（ENTRY/ADD/HOLD/TRIM/EXIT/STOP）完全兼容

# 五、方向五：买点/卖点精确触发功能（深度设计）

> **核心原则**：禁止自行设计，必须参考主流方法或工具，有学术/业界支撑。
> 本章所有方法均标注参考来源。

## 5.1 问题定位

当前系统买卖触发方式：

```
Signal → Decision(加权投票) → Strategy(行为约束) → Execution(成交)
```

问题：
1. **买点不精确**：Decision 给出"偏多"就买入，没有明确的入场价格
2. **卖点模糊**：卖出触发依赖信号评分阈值，不是精确的价格点位
3. **缺少多维度验证**：技术面、资金面、消息面各自独立，没有融合为一个"买卖触发点"
4. **没有最高优先级**：买卖点触发后应该覆盖信号投票，但当前没有这个机制

## 5.2 主流量化框架的 Entry/Exit 设计参考

### 5.2.1 Freqtrade 的 Entry/Exit 模型

Freqtrade 是目前最成熟的 Python 开源量化交易框架之一，其 buy/sell 信号设计被广泛验证：

```python
# Freqtrade 的典型买入逻辑
def populate_buy_trend(self, dataframe, metadata):
    dataframe.loc[
        (
            (dataframe['rsi'] < 30) &                    # 超卖
            (dataframe['volume'] > dataframe['volume_ma']) & # 放量
            (dataframe['close'] > dataframe['ema20'])     # 站上均线
        ),
        'buy'] = 1
    return dataframe
```

参考要点：
- 多个条件 AND 组合，不是加权投票
- 条件明确可回溯、可验证
- 买卖信号是布尔值，不是连续分数

### 5.2.2 Backtrader 的事件驱动模型

Backtrader 强调订单语义清晰：
```python
def next(self):
    if not self.position:  # 空仓
        if self.data.close[0] > self.sma[0]:
            self.buy(size=xxx, exectype=bt.Order.Limit, price=xxx)
    else:  # 持仓
        if self.data.close[0] < self.sma[0]:
            self.sell(size=xxx)
```

参考要点：
- 买卖点是明确的价格条件
- 支持 Limit/Stop/Market 等多种订单类型
- 入场和出场逻辑完全独立

### 5.2.3 Qlib 的多因子触发模型

Qlib（微软亚洲研究院）的决策生成器设计：
```python
# 信号 → 分数 → 阈值触发 → 交易动作
signal = model.predict(features)
if signal > top_quantile_threshold:
    action = BUY
elif signal < bottom_quantile_threshold:
    action = SELL
```

参考要点：
- 阈值基于历史分位数，不是固定值
- 买入阈值和卖出阈值不对称（买入更严格）

### 5.2.4 行业共识总结

| 共性 | 说明 |
|------|------|
| 买卖点 = 明确条件 AND | 不是加权投票，是条件 AND 组合 |
| 买卖逻辑独立 | 买入条件 ≠ 卖出条件的反转 |
| 阈值动态化 | 基于波动率/分位数，不是固定数值 |
| 多层过滤 | 趋势过滤 → 位置过滤 → 触发信号 |
| 订单类型明确 | Limit/Stop/Market 各有适用场景 |

## 5.3 买点（Entry Point）系统设计

### 5.3.1 买点方法论参考

| 方法 | 来源 | 适用场景 | 可靠性 |
|------|------|---------|--------|
| **突破买入** | Livermore, O'Neil CANSLIM | 强势股追涨 | 高（需配合量能确认） |
| **回调买入** | Elder, 缠中说禅 | 趋势中的低吸 | 高（需均线支撑确认） |
| **均线金叉** | 经典技术分析 | 趋势转折 | 中（滞后但稳定） |
| **MACD零轴金叉** | Gerald Appel | 中期趋势确认 | 中高 |
| **放量突破前高** | Minervini SEPA | 动量突破 | 高（机构行为特征） |
| **RSI超卖反弹** | Wilder | 超跌反弹 | 低（易接飞刀，需趋势过滤） |
| **北向资金转向** | A股实证研究 | 外资流入驱动 | 中（可用于确认） |

### 5.3.2 买点触发条件组合

参考 CANSLIM + Minervini SEPA 体系，设计以下买点触发规则：

```
【主买点 — 突破买入】
条件（全部必须满足，AND）：
  1. 价格突破 N 日高点（N=20）
  2. 突破日成交量 > 20日均量的 1.5 倍（放量确认）
  3. MA5 > MA20 > MA60（多头排列或即将形成）
  4. 沪深300年线牛市（index_close > index_ma250）
  5. 不在止损冷却期内（距上次止损卖出 > 10天）

触发动作：ENTRY，仓位=试探仓(10-15%)
```

```
【次买点 — 回调买入】
条件（全部必须满足，AND）：
  1. 价格回调至 MA20 附近（MA20 × 0.97 ~ MA20 × 1.03）
  2. 回调缩量（当日量 < 20日均量 × 0.8）
  3. MA20 > MA60 且 MA20 向上（中长期趋势仍向上）
  4. 前期涨幅 > 10%（确认是上升趋势中的回调，不是下跌趋势）
  5. 已持有试探仓且浮盈 > 0（有利润保护）

触发动作：ADD，仓位=基础仓(25-30%)
```

```
【辅助买点 — 北向资金确认】
条件（全部必须满足，AND）：
  1. 北向资金连续 3 日净流入该股
  2. 价格在 MA20 上方
  3. 已有技术面买点触发（北向资金仅作为增强确认，不作为独立触发）

触发动作：将原买点仓位提高一档
```

### 5.3.3 买点价格计算

参考 ATR（Average True Range）方法：

```python
# 突破买点价格
entry_price_breakout = max(近20日高点, 今日开盘价)
# 使用限价单，价格为突破位 + 0.3 ATR 容忍
entry_price = entry_price_breakout + 0.3 * ATR(14)

# 回调买点价格
entry_price_pullback = MA20  # 在20日均线附近挂单
entry_price = entry_price_pullback
```

## 5.4 卖点（Exit Point）系统设计

### 5.4.1 卖点方法论参考

| 方法 | 来源 | 类型 | 精确度 |
|------|------|------|--------|
| **移动止损** | 海龟交易法则 | 止损 | 高（跟踪最高点回撤） |
| **ATR止损** | Wilder, Elder | 止损 | 高（自适应波动率） |
| **固定百分比** | 通用 | 止损 | 中（简单但不自适应） |
| **均线止损** | 经典技术分析 | 趋势退出 | 中（滞后） |
| **Chandelier Exit** | Le Beau | 止损 | 高（结合ATR+最高点） |
| **Parabolic SAR** | Wilder | 止损/跟踪 | 中（盘整误触发多） |
| **北向资金流出** | A股实证研究 | 辅助退出 | 中（确认信号） |

### 5.4.2 卖点触发条件组合

```
【第一卖点 — 移动止损（Chandelier Exit 改进版）】
止损价格 = 持仓期间最高价 - N × ATR(14)

N值按仓位分层：
  - 试探仓: N=4（宽松，允许更大波动）
  - 基础仓: N=3（标准）
  - 重仓:   N=2（收紧，快速止损）

触发条件：收盘价 < 止损价格
触发动作：STOP（按仓位层级对应比例减仓）
```

```
【第二卖点 — 趋势破坏卖出】
条件（任一满足即触发）：
  1. MA5 下穿 MA20（短期趋势破坏）
  2. MA10 下穿 MA60（中期趋势破坏）
  3. 价格跌破 MA60 且 MA60 走平或向下

触发动作：
  - 短期破坏: TRIM（减仓40%）
  - 中期破坏: EXIT（清仓）
```

```
【第三卖点 — 止盈卖出】
条件（全部必须满足）：
  1. 浮动盈利 > 目标收益率
  2. 出现上涨乏力信号（RSI > 70 + 缩量 / MACD 死叉 / 上影线）

分批止盈：
  - 盈利 > 10%: TRIM 30%（锁利）
  - 盈利 > 20%: TRIM 40%（再锁一大部分）
  - 剩余 30% 用移动止损跟踪（让利润奔跑）
```

```
【辅助卖点 — 北向/主力资金流出确认】
条件：
  1. 北向资金连续 3 日净流出该股
  2. 主力资金连续 5 日净流出
  3. 已有技术面卖点触发（资金流出作为增强确认）

触发动作：将原卖点减仓比例提升一档（如 TRIM → EXIT）
```

### 5.4.3 卖点价格计算

```python
# Chandelier Exit 价格
highest_close = max(close_prices_since_entry)
stop_price = highest_close - N * ATR(14)

# 趋势破坏退出价格
exit_price = 次日开盘价  # 趋势破坏用开盘价立即退出
# 或 MA60 价格挂限价单（如果距MA60不远）
exit_price = MA60  # 适用于价格仍在MA60附近的场景
```

## 5.5 买卖点在七层架构中的位置

### 5.5.1 架构调整

```
当前架构：
Signal → Decision → Event → AI Modifier → Strategy → Execution

v0.8.3 调整后架构：
Signal → Decision → Event → AI Modifier → [EntryPoint/ExitPoint] → Strategy → Execution
                                           ↑
                                     买点/卖点模块
                                     (最高优先级)
```

### 5.5.2 优先级机制

```python
# orchestrator.py analyze() 中的优先级逻辑

def analyze(self, stock_data):
    # 1. 正常决策流程
    decision = self.decision_engine.make_decision(signals)
    
    # 2. 买卖点计算（最高优先级）
    entry_exit = self.entry_exit_calculator.calculate(stock_data)
    
    # 3. 买卖点触发 → 覆盖决策
    if entry_exit.exit_triggered:
        # 卖出点触发，直接覆盖为卖出
        decision = DecisionResult(
            signal=Signal.SELL,
            position_action=entry_exit.exit_action,  # EXIT or TRIM
            position_ratio=entry_exit.exit_ratio,
            overridden_by="entry_exit_point",
            overridden_reason=entry_exit.exit_reason
        )
    elif entry_exit.entry_triggered:
        # 买入点触发，直接覆盖为买入
        decision = DecisionResult(
            signal=Signal.BUY,
            position_action=PositionAction.OPEN,  # 或 ADD
            position_ratio=entry_exit.entry_ratio,
            overridden_by="entry_exit_point",
            overridden_reason=entry_exit.entry_reason
        )
    
    # 4. 继续走 Strategy → Execution
    return decision
```

# 七、开发原则重申

从 v0.8.2 延续的五条持久化原则：

1. **不再新增大层级**：买卖点模块在现有七层架构内以模块形式存在，不新增第八层
2. **先诊断再调参**：买卖点需先通过三轮对照回测验证，再调整参数
3. **先重构语义再重构参数**：买卖点是交易语义的进一步精化（从"什么时候买卖"到"什么价格买卖"）
4. **AI先做研究增强**：AI在此阶段仍负责信息理解（方向一），不直接触发交易
5. **优先修复拿不住赢家**：买卖点的移动止损机制直接服务于"让赢家充分奔跑"

# 八、结论

v0.8.3 的核心命题是：**从"能跑 + 能解释"走向"买得准 + 卖得好"**。

五个方向的优先级排序：
1. **P0 — 买卖点精确触发**（8-12天）：系统最重要的能力升级，需要最长的研发周期
2. **P1 — AI输入增强**（2-3天）：为买卖点提供更准确的消息面判断
3. **P1 — 金字塔仓位管理**（4-5天）：让仓位与买卖点自然联动
4. **P2 — RAG评估 + MEMORY清理**（2.5-3.5天）：维护性工作

买卖点功能不自行发明，所有方法均有明确学术/业界来源（Chandelier Exit / ATR / 海龟法则 / CANSLIM / SEPA / Freqtrade），并用真实 A 股历史数据进行三轮对照验证。
