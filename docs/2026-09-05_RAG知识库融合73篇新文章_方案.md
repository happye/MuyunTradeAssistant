## 一、项目现在如何处理这些文章（消费链路）

```
投资策略（持续更新）/*.txt|*.md
   ↓ src/rag/ingestion.py: load_strategy_files()   rglob 递归扫 .txt + .md
   ↓ _process_single_file()                         提取章号→分类元数据→分块(500字)
   ↓ src/rag/embedding.py: embed()                  BAAI/bge-small-zh-v1.5（失败降级 TF-IDF）
   ↓ src/rag/store.py: FAISSVectorStore.add()       IndexFlatIP 内积索引 + docs.json
   ↓ src/rag/retrieval.py: HybridRetriever          BM25(jieba) 0.4 + 语义 0.6，RRF 融合
   ↓ src/rag/context.py                             格式化注入 Chat / Event / AI-Modifier prompt
   ↓ knowledge/index/{index.faiss, docs.json, fingerprint.json}
```

**自动重建机制**：`service.py:316` 用 `fingerprint.json`（每个文件的 mtime）比对，文件数或 mtime 变化 → 下次启动自动全量重建。
→ **新增 73 个文件后，任何人下次跑 `start.py` 就会触发重建**，所以必须在那之前把 P0 修掉。

**关键事实：检索层（`retrieval.py`）完全不使用 metadata**。`category` / `quantifiability` / `applicable_layers` 三个字段建了但从未过滤——所有过滤能力形同虚设，检索结果只由向量相似度和 ID 决定。

## 二、新增 73 篇后的实测影响（审计脚本实跑，非估算）

审计脚本：`.workbuddy/tmp/muyun_scrape/audit_rag.py`（只读，可复跑）

| 指标 | 数据 |
|------|------|

| 摄入文档块 | **708 块 / 323,620 字** |

### 🔴 P0-1：doc_id 冲突 91 个 / 182 块（新增导致）

`ingestion.py:78` 的 `_get_chapter_number()` 用 `re.search(r'第(\d+)章', filename)`，
**「我的金融战争第10章 …」与「第10章 融资盘……」都解析出 chapter_num=10** → doc_id 都是 `ch10_p1`。

而 `store.py:112` 的 `self._id_to_idx[doc.id] = start_idx + i` 是字典赋值，**后者覆盖前者**；
`store.py:219` `get_doc_by_id()` 只返回最后一个 → **认知革命第10-65章中约 91 个块会被金融战争静默屏蔽，反之亦然**。

实测冲突样例：
```
ch10_p1 ← 我的金融战争第10章 机构围剿 | 第10章 融资盘——助涨助跌的放大器
ch13_p1 ← 我的金融战争第13章 磨盘拉锯 | 第13章 波浪理论——在随机波动中硬数浪
ch15_p1 ← 我的金融战争第15章 外盘扰动 | 第15章 图形陷阱：头肩底、W底
```

### 🔴 P0-2：旧索引 63% 是冗余重复（与新文章无关的既有缺陷）

```
旧 docs.json：1129 块，唯一内容仅 417 块，冗余 712 块
重复分布：306 组内容各存了 3 份，100 组各存了 2 份
例：'望周知—系统化交易大纲_p1' 这个 ID 出现 3 次
```
**后果**：语义检索 top_k=5 时，同一段内容可能占掉 3 个名额 → 检索多样性被稀释 60%；`docs.json` 2.15MB 里约 1.4MB 是垃圾。
**注意**：这是历史遗留（store 被重复 add 3 次），重建时单次 add 会自然消失，但**根因未修则下次还会复发**。

### 🟠 P1-1：分类映射表未覆盖新内容（全量误分类）

`ingestion.py:29` 的 `CHAPTER_CATEGORY_MAP` 只覆盖 1-65 章，其余走默认值：

| 内容 | 块数 | 当前分类 | 应为 |
|------|------|---------|------|
| 认知革命 第66-83章（热手谬误/情绪记录…） | 约 90 | `technical` | `psychology`（明显是 51-65 章心理篇的延续） |
| 交易千篇 84-105 + 451-459 | 112 | `market_analysis`（默认值） | 混合：84-99 情绪管理→`psychology`；101-105 止损→`risk_management`；451-459 熊市→`market_analysis` |
| 我的金融战争 1-31章 | 110 | `technical`（落入 range(1,12)） | `market_analysis`（交易纪实/案例，非技术教学） |

⚠️ 但注意：当前检索层不读这些字段，所以**误分类暂时不影响召回，只影响未来一旦启用元数据过滤时的正确性**——属于"现在不修，以后启用过滤就会错"的债。

### 🟠 P1-2：chapter 显示名歧义 29 个

`models.py:32` 的 `chapter` 属性用于 `context.py` 生成「【第10章】xxx」引用来源。
现在「第10章」既指认知革命的《融资盘》，也指金融战争的《机构围剿》——**AI 引用时来源无法区分，用户核对时会看到张冠李戴**。

### 🟢 P2：元数据三字段（category/quantifiability/applicable_layers）全链路未使用

`ingestion.py` 认真算了这些值，`retrieval.py` 一次都没读。属于"建了但没接线"。

## 三、方案选项

### 方案 A：修 ID + 补映射 + 重建索引（**推荐，改动小、风险可控**）

| # | 改动 | 文件 | 说明 |
|---|------|------|------|
| A1 | doc_id 加系列前缀，消除碰撞 | `src/rag/ingestion.py:69/316` | 系列识别：文件名含「我的金融战争」→`jrz{num}_p{i}`；「交易千篇」→`qp{num}_p{i}`；纯「第N章」→`rz{N}_p{i}`。彻底消除 91 个冲突 |
| A2 | metadata 新增 `series` 字段；chapter 显示名带系列 | `ingestion.py:301` / `models.py` | 「金融战争第10章」vs「第10章」，解决 P1-2 歧义 |
| A3 | 补齐分类映射 | `ingestion.py:29-66` | 66-83→psychology；金融战争→market_analysis + layers 限 `["Chat"]`；交易千篇按主题分段 |
| A4 | store.add 幂等化 | `src/rag/store.py:83` | 防止重复 add 累积（修 P0-2 根因），同 ID 覆盖而非追加 |
| A5 | 重建索引并验证 | 命令行 | 见第五节验证计划 |

### 方案 B：A + 检索层接上元数据过滤（深水区，改动中等）

在 A 基础上让 `HybridRetriever.retrieve()` 支持 `series` / `category` 过滤参数，`service.get_context()` 按调用方传场景：
- Chat 场景：全部系列可召回
- Decision / Strategy 场景：**排除金融战争**（小说叙事，不适合驱动买卖决策）
- Event / AI-Modifier：优先 market_analysis

价值：把 P2 那三个"死字段"真正用起来，同时解决第四节的稀释风险。

### 方案 C：只重建索引、不改代码（**不推荐**）

会自动触发，但将导致 91 组 ID 冲突 → 约 182 块内容被静默屏蔽，且屏蔽哪一半取决于文件遍历顺序（不可控）。属于"看起来加进去了，实际一半检索不到"。

### 方案 D：分系列独立索引（改动大）

两个 FAISS 索引 + 路由层。检索可控性最强，但要改 store/retrieval/service 三层的接口，回归面大。除非你要求"金融战争完全不参与策略检索"，否则性价比不如 B。

## 四、核心风险与缓解

**风险 1｜内容稀释**（必现）：新内容 222 块（金融战争 110 + 交易千篇 112）占重建后 708 块的 31%。
`default_top_k=5` 不变的话，问「止损怎么设」可能返回金融战争的小说情节而非交易千篇的实操规则。
→ 缓解：采用方案 B（决策场景排除小说系列），或把金融战争的 `applicable_layers` 限制为 `["Chat"]` 并在 context 构建处生效。

**风险 2｜小说叙事的语义干扰**：金融战争是纪实小说，大量"老王如何操作"的情节，语义上会与真实操作类查询相似，但答案是故事不是规则。
→ 缓解：同上 + 建议 chapter 显示名强制带「金融战争」前缀，让 AI 和用户一眼能识别。

**风险 3｜重建后索引反而变小**：1129 → 708 块。这不是内容丢失，而是旧索引 63% 冗余被清掉（唯一内容 417 → 708，实际**新增 70%**）。需要有心理预期。

**风险 4｜首次重建耗时**：708 块 × bge-small-zh 向量化，预计 1-3 分钟（首次加载模型另需下载/加载时间）。
