## 一、问题诊断

### 根因分析

SELL频繁不是策略库的问题，而是代码架构存在三个系统性缺陷叠加：

### 缺陷1：空仓时止损仍然覆盖BUY信号

**位置**：`decision_engine.py` → `_apply_action_signals()`

```python
# 当前代码：不管有没有仓位，止损都一票否决
for sig in stop_loss_signals:
    if sig.signal == SignalType.SELL and sig.confidence >= 0.8:
        return SignalType.SELL, f"⚠️ 止损信号覆盖：..."
```

**问题**：`_apply_action_signals()` 没有接收 `current_position_ratio` 参数，不知道当前是否有仓位。导致：
- 空仓时，5个base信号全是BUY → 止损信号覆盖为SELL → 错过买入机会
- 空仓时产生SELL信号 → `_calculate_position()` 中 `current_position_ratio < 0.05` 直接走STAY_OUT → 看起来"合理"但实际浪费了买入时机

**正确逻辑**：止损的语义是"保护已有仓位"，空仓时止损应该只作为风险提示，不应该否决BUY信号。

### 缺陷2：5%清仓阈值 → 减仓死亡螺旋

**位置**：`decision_engine.py` → `_calculate_position()`

```python
LOW_POSITION_CLEAR = 0.05  # 仓位<5%时直接清仓（太小无意义，交易成本不划算）
```

**来源**：这是v0.5.2中从10%下调到5%的。当时v0.5.1的10%阈值太容易触发（建仓20%，减仓留50%，一次就变10%→直接清仓），所以下调到5%。

**问题**：5%的阈值配合65%减仓保留率，仍然会形成4次减仓→清仓的螺旋：

```
建仓20% → 减仓留65%=13% → 减仓留65%=8.5% → 减仓留65%=5.5% → 减仓留65%=3.6% → <5%清仓
```

**5%阈值本身的逻辑没问题**——仓位太低确实交易成本不划算。问题在于：
1. 减仓后没有足够的保护期防止连续减仓
2. 建仓比例20%太低，4次减仓空间太小
3. 65%保留率意味着每次减掉35%，仓位下降很快

### 缺陷3：SELL决策没有门槛

**位置**：`decision_engine.py` → `_determine_final_signal()`

```python
# BUY有门槛：buy_score >= 0.25 且 > sell_score
# SELL没有任何门槛：只要 sell_score > buy_score 就是SELL
```

**问题**：BUY需要 buy_score >= 0.25 才能触发，但SELL只要 sell_score > buy_score 就是SELL——即使 sell_score 只有0.15。

加上regulator的放大效应（看空时SELL×1.3，BUY×0.6），很弱的看空信号也能变成SELL。

## 二、修复方案

### 方案A：止损仓位感知（必须修）

**修改位置**：`_apply_action_signals()` 和 `make_decision()`

**方案**：给 `_apply_action_signals()` 增加 `current_position_ratio` 参数

```python
def _apply_action_signals(
    self,
    action_signals: list[SkillSignal],
    current_decision: SignalType,
    data: StockData,
    current_position_ratio: float = 0.0,  # 新增
) -> tuple[SignalType, Optional[str]]:
```

**规则**：
- **有仓位（ratio > 0）**：止损逻辑不变，confidence≥0.8 一票否决
- **无仓位（ratio = 0）**：止损信号降级为风险提示，不覆盖BUY/HOLD，但可以压制弱BUY为WATCH
  - 具体规则：止损confidence≥0.8 + 当前决策是BUY → 降为WATCH（观望而非卖出）
  - 止损confidence<0.8 → 不影响

**理由**：空仓时止损的含义是"这只股票有风险，谨慎入场"，应该是"观望"而非"卖出"。

---

### 方案B：减仓保护期（动态实现）

**修改位置**：`backtest_engine.py` 和 `decision_engine.py`

**方案**：不是固定写死的天数，而是基于"同一减仓原因"的动态保护期

#### 实现思路

1. **新增减仓原因追踪**：在 `DecisionResult` 中记录最近一次减仓的原因和时间
   - `last_reduce_reason`: str（如"浅层止损"/"止盈"/"弱卖出"）
   - `last_reduce_date`: str（日期）

2. **保护期规则**：
   - **同一原因**不重复减仓（如连续两天都是"浅层止损"，第二天不执行）
   - **不同原因**可以减仓（如浅层止损后止盈触发，可以执行）
   - **保护期时长**取决于减仓原因的严重程度：

   | 减仓原因 | 保护期 | 理由 |
   |---------|--------|------|
   | 深度止损(≥0.85) | 0天（直接清仓，无需保护） | 趋势走坏 |
   | 浅层止损(<0.85) | 15天 | 短期波动已反应，给市场恢复时间 |
   | 止盈 | 10天 | 已经获利了结，等下一波 |
   | 弱卖出(sell<0.4) | 15天 | 弱信号不急，避免反复操作 |
   | 强卖出(sell≥0.4) | 5天 | 强信号可信度高，但也不宜每天减 |

3. **为什么不用固定天数**：
   - 固定15天在牛市里太长（错过回调后的加仓机会）
   - 固定5天在震荡市里太短（5天后又减仓，还是螺旋）
   - 动态方案根据减仓原因区分，浅层止损给更长保护（因为浅层止损容易反复触发），强卖出给短保护（因为强信号确实应该减）

4. **回测引擎改动**：
   - `BacktestEngine` 新增 `last_reduce_info: dict` 追踪减仓信息
   - 执行REDUCE前检查：是否在保护期内 + 原因是否相同

### 方案C：SELL决策门槛（分层门槛 v0.6.1 实现）

**修改位置**：`_determine_final_signal()`

**状态**：✅ 已完成

**背景**：方案D（年线牛熊判断）已实现，市场状态切换频率从1-2天→数周到数月，分层门槛有了可靠基础。

#### 最终方案：C3 分层门槛 + 强弱SELL区分

```python
# SELL分层门槛（基于方案D的稳定市场状态）
SELL_THRESHOLDS = {
    MarketState.RISK_OFF: 0.25,    # 熊市：灵敏卖出（该跑就跑）
    MarketState.PANIC: 0.20,       # 恐慌：更灵敏（极端行情先跑再说）
    MarketState.TRANSITION: 0.30,  # 震荡：中等门槛（多空不明不急卖）
    MarketState.RISK_ON: 0.35,     # 牛市：保守卖出（避免震荡洗出）
}

# 强SELL判定（门槛以上 + 明显强于BUY）
STRONG_SELL_RATIO = 1.2  # sell_score > buy_score * 1.2 才算强SELL
```

**核心逻辑**：
1. sell_score 必须达到当前市场状态的门槛（最低0.20~0.35）
2. sell_score 必须明显强于 buy_score（>1.2倍），否则偏向WATCH
3. 熊市/PANIC 门槛低（灵敏），牛市门槛高（保守）
4. 与止损/止盈的action信号覆盖不冲突（止损一票否决在第四步，不受门槛影响）

**为什么不选C1/C2**：
- C1（对称门槛0.25）太低，regulator放大后弱看空也变SELL
- C2（固定0.35+1.2倍）过于保守，熊市该跑时卖不出
- C3是策略库思路的直接体现："牛市做突破（不轻易卖），熊市做防守（该跑就跑）"

**与现有逻辑的关系**：
- 方案A（止损仓位感知）在第四步覆盖，不受SELL门槛影响
- 方案D（年线牛熊）提供稳定的state判断，门槛不会频繁变化
- 方案B（减仓保护期）限制减仓频率，与SELL门槛互补
- SELL门槛在第三步`_determine_final_signal`生效，是"普通投票"层面的过滤

**回测验证**（002192，2025-04-19 ~ 2026-04-19）：

| 指标 | v0.6.0（无SELL门槛） | v0.6.1（SELL分层门槛） | 变化 |
|------|---------------------|----------------------|------|
| 总资金收益率 | +40.98% | +45.65% | +4.67% |
| 交易次数 | 6买6卖 | 18买19卖 | ↑交易增多* |
| 最大回撤 | -11.14% | -11.14% | 不变 |
| 夏普比率 | ~2.0 | 2.09 | 略升 |

*注：交易增多是因为SELL门槛只过滤了"弱看空投票→SELL"，但止盈/止损的action覆盖不受门槛影响。减仓+加仓循环是止盈信号导致的，不是SELL门槛的问题。这是另一个维度的优化方向。

## 三、5%清仓阈值

**结论**：5%阈值本身不需要改，它的逻辑是正确的——仓位太低交易成本不划算。

问题不是5%阈值太低，而是前面的缺陷导致仓位快速缩水到5%。修复方案A（止损仓位感知）和方案B（减仓保护期）之后，仓位缩水的速度会大幅放缓：

- 修复后，空仓时止损不再否决BUY → 更容易建仓
- 修复后，同一原因15天内不重复减仓 → 不再4次减仓就清仓
- 建仓20%+减仓保护15天 = 至少15天才减一次 → 不会再4天清仓

## 四、中长期策略实现思路

### 当前差距

你的策略库有"月线定方向→周线定位置→日线找买卖点"的框架，但代码只用了日线数据。13个技能全是日线级别，对日线波动过度反应。

### 实现思路（三个阶段）

#### Phase 1：多周期数据基础设施

- **数据层**：Baostock已支持周线和月线数据（`query_history_k_data_plus` 的 `frequency` 参数）
- **StockData扩展**：增加周线/月线字段
  - `weekly_trend`: 周线趋势（BULLISH/BEARISH/NEUTRAL）
  - `monthly_trend`: 月线趋势
  - `weekly_ma5_above_ma10`: 周线MA5>MA10
  - `monthly_ma5_above_ma10`: 月线MA5>MA10
- **DataFeeder扩展**：同时加载日线+周线+月线数据

#### Phase 2：多周期共振升级

- **multi_timeframe.yaml 升级**：从只看日线均线，变成真正的多周期共振
  - 月线看多 + 周线看多 + 日线买入 → 强BUY（confidence×1.3）
  - 月线看多 + 周线看空 + 日线买入 → 弱BUY（confidence×0.7）
  - 月线看空 → 压制所有BUY信号（大方向不对，不抄底）
- **新增条件**：`weekly_bullish`/`weekly_bearish`/`monthly_bullish`/`monthly_bearish`

#### Phase 3：长周期过滤机制

- **趋势过滤器**：月线/周线方向作为"大局观"，只有大方向一致时才执行日线信号
- **减少噪音**：日线信号频繁波动是天性，但月线/周线趋势稳定得多
- **策略库适配**：你的策略库本来就是"月线定方向→周线定位置→日线找买卖点"，代码只是缺少周线/月线维度

**预期效果**：中长线操作，交易频率大幅降低（月线方向不变就不轻易卖出），收益更稳定。

## 七、方案D（新增）：市场状态判断改用A股行业标准

### 问题回顾

当前StateMachine用5个日线维度打分，其中2个（当日涨跌、当日成交量）每天都会变，导致状态1-2天就切换一次。C3方案按市场状态设SELL门槛，但状态本身不稳定，门槛跟着变反而更危险。

### A股行业通用的牛熊判断方法

#### 方法1：年线（250日均线）——A股最广泛使用的"牛熊分界线"

百度百科定义："牛熊线是股市技术分析中用于判断市场趋势转变的核心指标，主要通过250日移动平均线（年线）的走势变化进行判定。"

- **价格 > 250日均线** → 牛市
- **价格 < 250日均线** → 熊市
- **250日均线由上转下** → 牛转熊信号
- **250日均线由下转上** → 熊转牛信号

**变化频率**：极低。250日均线方向改变一年通常1-2次，价格穿越年线一年2-4次。

#### 方法2：20%涨跌幅法则——技术性牛熊市的量化定义

全球通用标准，A股机构同样采用：
- **技术性牛市**：从近期显著低点上涨超过20%
- **技术性熊市**：从近期显著高点下跌超过20%

**变化频率**：低。一轮牛熊周期1-3年，20%阈值很少频繁触发。

#### 方法3：MA50/MA200金叉死叉——机构常用

- **金叉（MA50上穿MA200）** → 牛市确认
- **死叉（MA50下穿MA200）** → 熊市确认

**变化频率**：低。金叉/死叉一年1-3次。

#### A股特有辅助验证

- **量价配合**：上涨需放量确认，无量上涨趋势不可靠
- **均线多头/空头排列**：MA5 > MA10 > MA20 > MA60 为多头排列
- **沪深300估值水平**：PE在10-17倍区间为正常，超出/低于为极端
- **北向资金**：单日净买入>200亿预示中期底部

### 方案D设计：基于年线的市场状态判断

用**沪深300指数的年线（250日均线）** 作为牛熊分界线，替代当前的5维度日线评分。

#### 状态定义

```python
# 基于沪深300指数（代表大盘整体走势）
# 数据已可用：baostock查询sh.000300的历史K线

RISK_ON（牛市）: 沪深300 收盘价 > 250日均线
    - 且 沪深300 收盘价距近250日高点回撤 < 15%

RISK_OFF（熊市）: 沪深300 收盘价 < 250日均线
    - 且 沪深300 收盘价距近250日高点回撤 > 20%

TRANSITION（震荡）: 介于两者之间
    - 价格在年线附近（±3%以内）
    - 或回撤幅度在15%-20%之间

PANIC（恐慌）: 保持现有逻辑
    - 当日跌幅 > 5%
    - 或 跌破MA60 + 放量暴跌（>2倍均量 + 跌>3%）
```

#### 为什么用沪深300而非个股数据

1. **大盘决定个股环境**：你的策略库第42章"牛市做突破，熊市做反弹"说的就是大盘环境
2. **沪深300更稳定**：300只成分股平滑了个股波动
3. **行业惯例**：QMT等量化平台都用沪深300作为基准指数
4. **数据已可用**：DataFeeder已经加载沪深300数据（index_trend/index_close/index_ma20/index_ma60）

#### 数据需求

需要新增：沪深300的250日均线（index_ma250）

已有：沪深300收盘价、MA20、MA60、趋势方向

#### 预期效果

| 对比项 | 当前方案 | 方案D |
|--------|---------|-------|
| 数据周期 | 日线（MA5/MA20/MA60） | 250日均线（年线） |
| 状态切换频率 | 1-2天 | 数周到数月 |
| 判断依据 | 当日涨跌+成交量 | 长期趋势+回撤幅度 |
| A股行业认可度 | 无（自编） | 高（年线=牛熊分界线，行业共识） |

#### 如果判断错误怎么办？

年线法可能"滞后"——价格跌破年线时可能已经跌了不少。但这是**特性而非缺陷**：

1. **年线判断的是趋势，不是拐点**——它的目的是告诉你"大方向是什么"，不是"明天会不会跌"
2. **滞后是安全垫**——确认熊市时已经跌了，但至少你不会在震荡中被反复洗出去
3. **PANIC机制兜底**——极端暴跌（>5%）仍然会触发PANIC状态，不受年线滞后影响
4. **TRANSITION区间缓冲**——年线附近±3%是灰色地带，信号不会直接翻转

### 方案D与方案A/B/C的关系

- **方案D是基础设施**——市场状态判断是整个决策系统的地基（✅ 已完成）
- **方案A（止损仓位感知）** 不依赖方案D，可以独立实现（✅ 已完成）
- **方案B（减仓保护期）** 不依赖方案D，可以独立实现（✅ 已完成）
- **方案C（SELL门槛）** 依赖方案D的稳定状态判断——分层门槛需要可靠的市场状态（🟢 开发中）
- **实施顺序**：A → D → B → 验证效果 → C（当前）
