## 三、D03 深挖：score=0 安全网链条与 TRIM 实测修正

本轮最有价值的发现，完整链条值得记录（防后人再犯）：

1. `make_decision` 的 action 一票否决（止损 conf≥0.8）直接返回 SELL，但 `weighted_scores` 里 SELL 桶来自 base 投票——被覆盖时恒为 0。
2. `strategy_layer.process` 的 `_needs_confirmation`（弱信号需确认）与 `_apply_reverse_cost`（score < 0.003 视为噪音）都挂在 score 上 → SELL 被降级 HOLD。
3. HOLD 分支的加仓判断 `buy_score > sell_score * 1.5` 在止损当日放行 ADD。**实测：RISK_ON 状态下止损触发当日 ADD 0.40 仓位，高质量 ADD 0.60。**
4. 主审首版修复只兜了 decision_engine + orchestrator 的 **CLOSE_ALL** 分支，注释里写"TRIM 减仓不兜底——影响远小于清仓"。**601318/2024 复跑残留 2 例 score=0**，定位探针（埋 trace 抓现场）显示两例都来自 `trend_break` 的 **MA5<MA20 短期信号 → exit_action="TRIM" → REDUCE 分支**——而 decision 已被强设 SELL、score 仍是 0，照样被降级反手 ADD。
5. **修正**：兜底条件挂 `force_exit`（安全网是否触发）而非 `position_action`（清仓 or 减仓）。减仓量级由 position_action 控制，与 score 正交，两者不该耦合。新增回归测试 `test_trend_break_trim_also_raises_score` 锁死这个写法。

> **教训**：修"安全网被降级"这类问题，判据是**谁触发的**（确定性安全网 vs 普通投票），不是**动作多重**（清仓 vs 减仓）。"影响小所以不修"的直觉判断被 60 秒的探针复跑推翻——**残留复跑是验收的一部分，不是可选项**。

## 六、git 损坏事故与无损修复（主审事故，如实记录）

**事故**：主审在执行 `git stash push`（为做 A/B 对照暂存源码）时进程被中断，`.git` 引用层损坏——`git status` 报 `fatal: bad object HEAD`，fsck 报全部 ref `invalid sha1 pointer`。

**损失评估（逐层核实）**：
- 工作区文件：**完好**（全部修复经 grep/测试逐项验证）。
- 对象库：`git cat-file --batch-all-objects --batch-check` 实测 650 个对象中仅 7 个 commit 可解析（2026-05-12 前历史 + 1 个 2026-07-16 的 WIP stash 快照 f27577f）；2026-05 之后的提交历史对象**已损坏丢失**。
- 远端：`origin`（私有仓库）应持有完整历史，但无凭据无法非交互拉取。

**修复（无损）**：损坏 `.git` 整体归档为 `.git.corrupted_20260830/`（另有一份 `/tmp/d04_rescue/git_backup_dotgit`）→ `git init -b main` 重建 → 配回 origin → 全工作区快照 commit **`0e9471c`**（461 文件）→ `git fsck --full` 零错误、status 干净。**没有任何文件被删除；历史嫁接待用户凭据**：

```
# 用户在有 GitHub 凭据的终端执行（GCM 会弹浏览器授权）：
git fetch origin
git reset --soft origin/main      # 历史回到远端，工作区与暂存保持现状
git commit -m "feat: v0.8.7.8 第四轮对抗审查D区块修复(ISS-072)"
git push
```

**根因与防复发**（已落 `.learnings/ERRORS.md` ERR-20260830-001）：`git stash` 与一切**有副作用的写操作**（stash/checkout/reset/rebase）都不该在 agent 的长任务链里裸跑——先 `git stash list` 确认栈状态、操作后立刻 `git status` 自检；A/B 对照改用**可还原的文件级原地切换**（备份→改→跑→还原→md5 校验），不再动 git 索引。
