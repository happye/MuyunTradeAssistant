🔴 事故定论：你的电脑为什么重启了三次

直接责任是我。我在 configs/settings.yaml 里把新加的重排器写成了 enabled: true（默认开启），而你机器上的 RAG 服务在每次跑 start.py / 分析 / chat 时启动，都会自动加载重排模型。后果是进程内存需求从约 1.2GB 暴涨到约 3.5–4GB（见下方内存账本），叠加当时我后台还在跑的多个验证进程，内存耗尽触发 Windows 硬件级保护重启。

你每次重启后重试，配置没变，于是「一跑就重启」稳定复现三次。确切的保护机制（内存耗尽 / 温度 / 电源）我无法远程确诊，但「一跑模型就重启」+ 双模型内存账本，指向内存耗尽的置信度极高。

已止血：reranker.enabled 已改回 false，残留 Python 进程已清零（tasklist 核实无残留）。你现在跑 start.py，行为和昨晚 106d50e 完全一致，不会再加载重排模型。
