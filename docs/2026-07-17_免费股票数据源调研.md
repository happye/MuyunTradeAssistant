## 0. 前提声明与置信度（必须先读）

### 0.1 WebSearch 全程失效 -- 诚实声明

本次调研原计划按 ISSUES.md:900 的方法论纪律"动手前先 web search"做 2026 实证。但**本会话 WebSearch 工具全程失效**：
- 主会话直连：4 个查询（中英文混合）全部只返回占位元响应（"I'll search for…"），零结果、零 URL。
- 3 个并行子 agent：分别 11 / 6+ / 6+ 次查询，全部空响应，3 个 agent 独立确认。
- 本会话无 WebFetch，`preview_*` 是本地 dev server 调试专用，无外部爬取能力。

**所以"全网调研"实际上没联上网。** 凡涉及"2026 年某源额度是否还在 / 是否停服"的时效性结论，**全部未网实证**，已逐条标注。这是本次调研最大的局限，请审阅时把数字当方向性参考。

### 0.2 但用了比网搜更强的替代验证

WebSearch 失效不代表全凭记忆拍脑袋。对**项目已安装的三个库**（akshare 1.18.51 / baostock / efinance 0.5.8），做了两类更强验证：

## 1. 核心发现：这不是"发现新问题"，是把已知 TODO 具体化

### 1.1 项目早已精准诊断（2026-07-15，ISS-055 评估结论）

3 个调研 agent 都"重构了问题前提"，但读 ISSUES.md 发现：**项目自己 2026-07-15 就在 ISS-055 里写清楚了**（ISSUES.md:1310-1326）：

> - **根因**：`effective_grade` 硬闸门立在 `industry_prosperity` 上，而这恰是 AI 最难判真的维度。**闸门立在最软的柱子上。**
> - **方向 1**：评估 effective_grade 闸门输入能否加客观数据（**行业营收增速/价格指数**）降低 AI 主观依赖。
> - **评估结论**：治本需客观数据源（行业营收增速/价格指数）--数据工程，非技术层代码修复，**建议笨总数据战略**。
> - **effective_grade 公式属笨总域**：硬封顶/软封顶/降权均=动公式，**不擅自动**（需笨总拍板）。
> - **第 3 层 gap 诚实声明**：**治本未做**：客观数据源降低 AI 主观依赖--数据工程撞天花板，留笨总数据战略。

记忆 `project_ai_ceiling` 也早写了：`industry_prosperity.py` 只喂「行业名 + 30 天新闻标题（≤10 条）」，缺钢价/产能利用率/库存周期/地产开工/政策落地；换强模型无用（garbage in garbage out）。

**所以本次调研不是发现新大陆，而是把 ISS-055"方向 1（加行业营收增速/价格指数客观源）"这个 TODO，落实成具体的、零新依赖的、实测可用的接口清单。** 这一点必须诚实，不能假装"覆盖了项目不知道的问题"。

### 1.2 瓶颈定位（亲自核实，非二手转述）

我读了 `industry_prosperity.py` 全文 + `auto_scorer.py` + `rule_scorer.py`，确认：

| 位置 | 现状（第一手核实） |
|---|---|
| `industry_prosperity.py:39-100` | AI 版景气度：输入仅 `industry_name` + `announcements`（新闻标题≤10条），喂 LLM 打 0-100。**零结构化景气数据。** 行业名+新闻都空时 `_missing_data_result`，AI 失败时 `_ai_failed_result`，都返回 `confidence=0, score=50`。 |
| `auto_scorer.py:170` | 维度评分器异常兜底：`score=50, conf=0`。 |
| `auto_scorer.py:221-229` | **ISS-055 透明度警告已落地**：`pros_conf==0` 时追加"⚠ 景气度数据缺失：评分为兜底值50（非真实判断）"。**agent 漏提了这点**--项目已经有警告了，交接文档第 20 行"已加警告"即此。但警告只提示、不提升判断质量，**治标不治本**。 |
| `rule_scorer.py:60-87` | 规则版景气度：用**个股近 20 日涨幅**代理行业景气，代码注释自承"粗糙"。回测定 mode 走的就是这个 rule 版（ISS-046 方向性结论）。 |
| `data_provider.py:get_data_summary` | 拉的字段：`business_intro / announcements / industry / kline / market_turnover`。**没有任何宏观/财务/景气/预告/预期字段。** |

**3 个 agent 独立交叉确认**同一结论（agent 3 给 `rule_scorer.py:60`，和我核实一致）。

### 1.3 对"AI 天花板是数据问题"的精确化

记忆 `project_ai_ceiling` 的判断方向正确，本次调研把它**精确化**：

- 原判断："景气度撞数据供给天花板"
- 精确化："天花板有两层--(1) **接线层**：`industry_prosperity` 压根没接结构化数据，akshare/baostock 里现成的 PMI/景气指数/营收增速/预告/预期一行都没调；(2) **供给层**：官方分行业景气指数、开工率/库存深度数据仍付费墙（卓创/百川/Wind）。"
- **第一层靠零新依赖就能大幅抬高**（本次报告核心）；第二层才是真天花板，绕不过但宏观 PMI/PPI 已隐含结论，对个股择时够用。

## 3. 外部新源全景（⚠️ 训练知识，WebSearch 查无实证，接入前必须人工核实）

### 3.1 tushare（tushare.pro，积分制）--⚠️ 有被否先例

- **覆盖**：财务三大表+指标/业绩预告快报/龙虎榜/板块/研报/股东/分红/宏观/行情/新闻，**最全**。
- **额度**：⚠️ 训练知识：注册送 120 积分；基础行情低门槛，**财务/龙虎榜/研报等高价值接口需 2000–5000+ 积分**；积分靠社区贡献或付费。需 token + 手机注册。
- **2026 可用性**：⚠️ 仍活跃维护，但 2024-2025 限流持续收紧传闻。**待验证**。
- **适用性**：理论上最对口"基本面拉不到"，但：**(a) 项目曾评估并否决**（`docs/v0.8.6_调研报告.md:314-324` D2 选项，嫌积分门槛，选了 D1 akshare+手填）；(b) 积分与"免费"目标冲突；(c) 真治本可能要付费。
- **建议**：**仅在 §2 已装库接口验证后仍不够时，再作为"治本付费路径"重新评估**，而非首接。

### 3.2 聚宽 joinquant / 米筐 ricequant --⚠️ 待验证

- 聚宽（joinquant.com，`jqdatasdk`）：行情/历史K/财务三大表/因子/龙虎榜/宏观/概念，**数据质量高字段全**。⚠️ 曾"注册即享免费"，2023 起大幅收紧，现多需手机+实名，免费额度小按调用计费。
- 米筐（ricequant.com，`rqdatac`）：行情/财务/因子/期货/宏观。⚠️ 免费试用有限，需 license key。
- **适用性**：质量优于 akshare 但有认证+配额成本，项目偏好无 token 路径，**优先级低于已装库现有接口**。

### 3.3 优矿 datayes / 万矿 windquant --⚠️ 免费含金量最低

Wind 数据库子集，财务/宏观/景气字段最权威（Wind 是机构标配），但社区版免费额度小、高价值字段（行业景气）仅付费。**不建议作为主源**，仅作"想验证行业景气是否有免费口子"的探查对象。

### 3.4 问财 iwencai / 雪球 --⚠️ 反爬合规成本高，不建议主源

- 问财（iwencai.com）：自然语言选股，结果含财务指标列可导出。**无官方 API**，需爬虫模拟，同花顺反爬严。
- 雪球（xueqiu.com）：行情/基本面/讨论热度。**无官方 API**，cookie/token 频繁失效，反爬持续加强。
- **适用性低**：数据 akshare 基本能覆盖，反爬维护成本+合规灰色不值得。问财可作"笨总手动选股辅助"或一次性研究。

### 3.5 巨潮资讯网 cninfo --✅ akshare 已封装在用

最权威的一手公告/年报/季报披露源。`stock_zh_a_disclosure_report_cninfo` 项目已在用（`data_provider.py:160` 备用新闻源，v0.8.6.5 修了 market 参数 bug）。**直接走 akshare 封装即可，无需独立接 cninfo**。

### 3.6 pytdx / mootdx（通达信协议）--⚠️ 对基本面短板无帮助

直连通达信行情服务器，拿实时行情/盘口/分时/历史K/五档。**通达信协议就是行情协议，基本不提供财务/景气/龙虎榜。** 仅在"所有 http 行情源全挂"时有冗余价值，**优先级低**。

### 3.7 GitHub 爬虫/聚合项目 --⚠️ 合规+维护风险

除头部（akshare/efinance/mootdx）外多为玩具/停更（star 数无法查证，不编造）。爬虫类可能违反目标站 ToS、有封号/法律风险，无 SLA。**不建议接入**。

## 4. 海外源（对 A 股国内个股增量小，诚实结论）

海外源对 A 股覆盖"有但弱--只有日线、常延迟/缺数据、配额极低"。akshare+baostock 在 A 股本地数据上本来就是顶级方案。

| 源 | A股覆盖 | 免费额度 | 2026可用性(未实证) | 价值 |
|---|---|---|---|---|
| **Stooq** | ✅ `.cn` 后缀日线 CSV | 无 key 无硬配额 | ⚠️ 多年稳定 | **唯一值得常驻**：给 akshare 日线做交叉校验 |
| **GDELT** | 全球新闻/事件结构化 | 免费、无 key | ⚠️ | **值得一试**：对"景气度撞墙"痛点补宏观/事件维度 |
| **Twelve Data** | ✅ 日线 | 800 次/天 | ⚠️ | Stooq 的配额制备选 |
| yfinance / Yahoo 直连 | ✅ `.SS`/`.SZ` 日线 | 无 key | ⚠️ 不稳（429 频发） | 交叉校验备选 |

**对 A 股项目实际有补充价值的海外源**：仅 **Stooq**（日线交叉校验）+ **GDELT**（宏观事件特征）。其余对 A 股国内个股无用。若策略扩展到**港股/中概 ADR**，海外源才有真正增量（yfinance/Finnhub 对港股中概覆盖好）。

## 5. 推荐方案（按 ROI 从高到低）

### 🥇 方案 A：零依赖接线治标（宏观景气 + 季频财务 + 业绩预告 → industry_prosperity）

**这是 ISS-055"方向 1"的具体落地，性价比最高，零新依赖。**

- **数据**（全部 ✅ 实测可用）：
  - 宏观：`macro_china_enterprise_boom_index` + `macro_china_pmi` / `cx_pmi_yearly` / `industrial_production_yoy` / `ppi`
  - 个股预告：baostock `query_forecast_report`（项目已封装，复用即可）
  - 全市场预告：`stock_yjyg_em`
- **做法**：在 `data_provider.get_data_summary` 加 `macro_prosperity` 字段（拉上述宏观序列最新值 + 个股预告），传给 `industry_prosperity.score()` 的 `user_prompt`。LLM 从"只看新闻标题"升级到"看 PMI 拐点 + 工业增加值 + 该股业绩预告同比 + PPI"。50 兜底触发条件从"新闻空"变成"宏观+预告+新闻全空"。
- **成本**：全免费、akshare 已装、无新依赖。实测数据新到 2026Q1 / 2026-04。
- **预期**：直接打掉"靠新闻猜景气"的接线层天花板。
- **诚实边界**：官方统计局"分行业景气指数"仍不在免费源内；开工率/库存深度数据付费墙（见 §6）。天花板抬高但没消失。

### 🥈 方案 B：baostock 季频财务接进景气/基本面维度

- **数据**：`query_growth_data`（营收/净利增速）+ `query_profit_data`（ROE/净利率）。**项目装了从没调过。**
- **做法**：按行业聚合成分股营收增速 → 行业景气代理（ISS-055:1313 明确要的"行业营收增速"）；个股级 ROE/净利率客观化业务纯度/风险维度。
- **成本**：零新依赖，baostock 已登录。
- **价值**：补方案 A 缺的"行业营收增速"客观层（方案 A 偏宏观）。

### 🥉 方案 C：efinance 异构冗余（补龙虎榜/股东/资金流）

- **数据**：`get_daily_billboard` / `get_top10_stock_holder_info` / `get_latest_holder_number` / `get_history_bill`。
- **价值**：补 akshare 未用的龙虎榜/股东/资金流，且与 akshare 异构封装可互为冗余（反爬时点不同）。
- **诚实边界**：与 akshare 同源（东财/同花顺），**不绕过东财反爬**，只是另一套失败重试路径。

### 方案 D：分析师一致预期做景气拐点代理

- **数据**：`stock_research_report_em`（含 2026-2028 EPS/PE 一致预期）+ `stock_profit_forecast_ths`（机构数+预期均值）。
- **做法**：个股级算"一致预期 EPS 较上年实际值增速"作为景气先行分；机构覆盖数作为置信度。可独立做 rule-based 预期子分，或并入方案 A 的 prompt。
- **价值**：解决"宏观景气好但个股预期下修"的误判。

### tushare（治本付费路径，不首接）

仅当方案 A/B/C/D 验证后仍缺"权威分行业景气/完整三大表历史"时，再重新评估 tushare pro（项目曾以 D2 否决，嫌积分）。**接入前务必人工核实 tushare.pro 当前免费积分与高价值接口门槛**（WebSearch 查无实证）。
