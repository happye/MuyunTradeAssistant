# 行业数据层跨模块适用性评估

> 日期：2026-08-16（夜间自主优化轮）
> 触发：用户要求"看看其他模块，尤其是重点模块是否也能应用这一套（产业链数据层/图谱），并且注意是否真的适合才能用"
> 结论先行：**只有 2 个模块真适合**（l 个股分析=只读展示，可安全落地；bz 景气度=数据对口但有回测红线，只出设计不落地）。其余模块明确**不适合**，理由见矩阵。

---

## 一、评估矩阵

| 模块 | 适合？ | 判定 | 理由 |
|------|--------|------|------|
| **l / la 个股分析** | ✅ 适合（只读展示） | **已落地**（本轮） | 在个股报告加"产业链定位"一行（该股处于哪条链哪个环节），纯展示不改任何评分/决策逻辑，零风险 |
| **bz 笨总景气度** | ⚠️ 数据对口但**有红线** | 只出设计，**不落地** | `industry_prosperity` 只吃"行业名+30天新闻标题"（ISS-055 已诊断），是全项目最饿数据的模块。但接线=改气宗评分行为，**红线：必须配回测验证 + bump CACHE_VERSION**（docs/2026-07-17 调研报告 §6.1/6.2）。夜间自主轮不做无回测的行为变更 |
| scan market 全市场扫描 | ❌ 不适合 | 排除 | 扫描器定位是**技术面初筛**（形态/量价过滤，毫秒级评估数百只股）。注入行业基本面数据会：(a) 拖慢全市场扫描（每个候选股一次网络调用）；(b) 改变"技术面初筛"的语义边界。想看行业面的用 chat analyze_industry，两者不该混 |
| expect 事件日历 | ❌ 不适合 | 排除 | 事件驱动逻辑=新闻/公告关键词扫描，与行业供需结构无关。强行加产业链数据是无关联的复杂度 |
| 回测 BacktestEngine / DataFeeder | ❌ **绝对不适合** | 排除（红线） | **No future-info injection**（CLAUDE.md 硬约束）。商品价格日线虽是历史数据，但回测引擎的输入契约是"当时可见的股票行情"，加新数据列=改变回测语义且需要全套重验证。不动 |
| Web UI | 🟡 以后再说 | 挂起 | 技术上适合（把 analyze_industry 报告渲染成页面），但 Web UI 本身是预览级，先把 CLI/TUI 做扎实 |
| AIModifier（AI情绪调节） | ❌ 不适合 | 排除 | 它已注入 RAG 策略知识+技术面背景，输入是新闻情绪分析，行业供需数据与其调节职责（情绪→分数修正）不对口 |

## 二、已落地：l 命令产业链定位（只读展示）

**实现**：[akshare_client.py](../src/data/akshare_client.py) 无侵入；在 [cli/main.py](../src/cli/main.py) `analyze_live` 报告头部加一行：

```
产业链定位: 锂电 · 上游·锂矿采选-锂辉石（图谱来源: 手写）
```

- 查 `industry_chains.yaml` + `industry_chains_auto.yaml` 的公司映射（`_company_codes`），股票代码命中即显示
- 不在任何链 -> 不显示（无噪声）
- 纯展示：不进评分、不进决策、不进回测

## 三、bz 景气度接线设计（未落地，留给笨总拍板）

**为什么对口**：ISS-055 定调"闸门立在最软的柱子上"（industry_prosperity 靠 AI 猜），2026-07-17 调研报告方案 A 明确指出接线层天花板=现成接口没接。现在 `industry_data.py` 恰好就是那批接口的落地。

**接线草图**（实施时参考）：
```
data_provider.get_data_summary(code)
  -> 新增字段 industry_data:
     match_chain(行业名) 命中 -> 商品价格分位文本 + 仓单趋势文本 + 需求文本
     （复用 build_industry_report 的三个 section，纯文本喂 prompt）
industry_prosperity.score() 的 user_prompt 注入上述文本
  -> AI 从"看新闻标题猜"升级为"看价格分位+库存方向+需求增速打分"
```

**验收门槛（缺一不可）**：
1. 回测对比：接线前后同参数跑（周末 5 年回测任务正好是载体）
2. `src/core/benzong/cache.py` bump `CACHE_VERSION`（否则改了不生效，命中旧缓存）
3. `effective_grade` 公式不动（笨总域）
4. 兜底条件变严：宏观+商品+新闻全空才给 score=50 兜底

**预期收益**：景气度维度从 conf≈0（纯猜）提升到有客观锚；透明度警告（auto_scorer.py:221）触发率下降。

## 四、维护责任划分（谁负责不过时）

| 资产 | 过时风险 | 维护机制 |
|------|---------|---------|
| 手写图谱（6条） | 低频缓慢（公司名单半年级别变化） | 人工编辑 yaml；`chains` 命令可见性监督 |
| 自举图谱 | 中（AI 当次梳理+30天行业变化） | created_at 落盘；>30天在报告头提示重新分析；同名重存自动覆盖刷新；`chains rm` 可删 |
| 知识库方法论 | 极低（框架性知识不随时间失效） | 无需维护；RAG 指纹自动重建 |
| 商品映射表（13链） | 低（期货品种罕见变动） | 接口台账登记；失效表现为[数据缺失] |
| 接口本身 | 中（反爬/改版） | docs/数据接口台账.md 登记实测状态；THS 封禁观察点已写明 |

**冗余控制**：自举图谱同名覆盖（不会越写越多条）；每条 2-4KB，50 个行业≈200KB yaml，加载毫秒级，无容量问题；别名冲突手写优先。

**能力衰减**：不会。降级链完整--图谱缺失走通用引擎、接口失败走[数据缺失]、THS 封禁走板块缺失提示，任何一层挂了 AI 仍能基于剩余数据+框架作答并明说缺口。
