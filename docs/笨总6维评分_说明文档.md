> 版本：v0.8.6.2（2026-06-20 实测通过）
> 关联：ISS-040 / ISS-041 / ISS-044 | 立项调研见 `docs/v0.8.6_调研报告.md`

本文档讲**评分器本身怎么工作**（不是笨总策略哲学——那部分见调研报告）。读完能回答：6 维怎么算分、数据从哪来、AI 和算法各管什么、降级时怎么办、命令怎么用、输出怎么看。

## 一、它解决什么问题

笨总体系的核心是「超景气价值投机」：先认高景气行业 + 现象级拐点，再用 6 维打分表给个股定量。这套打分表原本是 xlsx 课件（`笨总课件/笨总选股打分表.xlsx`），人工填 6 个分。本评分器把它工程化：**输入股票代码，自动出 6 维分 + 总分 + 等级**。

> **大前提（最重要）**：行业景气度 = 0 时整个模型失效。笨总教学 2 的反面案例——中免：行业景气 0 + 其他维度全 100 → 仍然 0 分。模型是乘号关系，不是加号。评分器会检测到这点并输出 `⚠ 大前提失效` 警告。

## 二、6 维打分公式（严格忠于 xlsx）

```
总分 = ( 行业景气度×0.20
       + 业务纯度×0.40      ← 权重最大
       + 历史估值位置×0.25
       + 细分行业龙头×0.15
       + 市场辨识度×0.20
       + 个股风险值×(-0.20)  ← 扣分项，0=最好
       ) × 流动性系数
```

权重之和：0.40+0.25+0.15+0.20+0.20-0.20 = 1.00（与 xlsx C 列一致）。

**流动性系数**（按全市场单日成交额，万亿）：

| 成交额 | 系数 | 含义 |
|--------|------|------|
| ≤ 0.8 万亿 | ×0.8 | 缩量市场，流动性折价 |
| ≥ 1.5 万亿 | ×1.2 | 放量市场，流动性溢价 |
| 其他 | ×1.0 | 正常 |

**等级阈值**（基于原始总分，严格忠于 xlsx，仅供 Excel 保真/审计）：

| 等级 | 分数 | 含义 |
|------|------|------|
| A | ≥ 90 | 超优质标的 |
| B | 80-90 | 优秀，可买入（HND 83.2 / THS 84.6 都是 B 级买入） |
| C | 60-80 | 可观察 |
| D | 40-60 | 勉强观望 |
| F | < 40 | 放弃 |

公式实现见 `src/core/benzong/scorer.py`（`BenzhongScore` + `score_one`），与 xlsx 严格对齐，试金石测试 7/7 PASS（HND=83.2 / THS=84.6 / 中免反面=120 触发大前提警告）。

**实际等级 `effective_grade()`（展示/决策用，含行业景气度硬闸门，ISS-047）**：

原始 `grade()` 有个致命误导——行业景气度只占 20% 权重，会被业务纯度 40%+估值 25% 淹没，导致"行业景气度只有 30 却评 A 级"（如医药龙头迈瑞）。但笨总体系第一大前提就是「没有高景气行业判断，其他维度再高也无意义」（中免反面案例）。所以新增 `effective_grade()` 把景气度做成硬闸门：

| 行业景气度 | 实际等级上限 | 笨总含义 |
|-----------|------------|---------|
| = 0 | **F**（模型失效） | 景气归零，不可作买入依据 |
| ≤ 30 | 最高 **C** | 边际下行，不能是买入级 A/B |
| ≤ 50 | 最高 **B** | 稳定无拐点，不能是顶级 A |
| > 50 | 取原始等级 | 真景气，正常评级 |

展示层（`bz`/`bz scan`/`l`）和决策层（`pos add` 定气宗/剑宗）一律用 `effective_grade()`，景气度 ≤30 标红 + 标注「原 X 级」。`grade()`/`total_score` 保持不动以保 Excel 试金石。

> **ISS-055 透明度补充**：当评级被景气闸门降级（`effective != grade`）**且**景气判定置信度 < 0.5 时，`auto_scorer` 额外追加一条警告「降级依据最不可靠维度（AI难判真/撞数据天花板），建议人工复核景气判断」。闸门公式不动（笨总域），仅在降级依赖低置信度景气判断时暴露脆弱性；高置信降级不扰民，ip==0 由原有「大前提失效」警告覆盖。

## 三、6 个维度：AI 还是算法？数据从哪来？

这是理解评分器的关键——6 维并非都用 AI，分两类：

| # | 维度 | 模式 | 数据来源 | AI 做什么 |
|---|------|------|---------|----------|
| 1 | 行业景气度 | 🤖 AI | Baostock 行业归属 + 新闻（em）| 综合判行业二级市场景气度 0-100，含四要素（真实性/传播性/规模性/时效性）考量。笨总评分标准内嵌在 SYSTEM_PROMPT，不依赖 RAG |
| 2 | 业务纯度 | 🤖 AI | 同花顺主营介绍 `stock_zyjs_ths` | 读主营介绍，判主营占比（≥90% 满分）+ 区分真主营 vs 蹭概念 |
| 3 | 历史估值位置 | 📐 纯算法 | Baostock 近 3 年日 K | 当前价 vs 3 年最低价涨幅：<20% 满分，每多 1% 扣 1 分，>120% 为 0 |
| 4 | 细分行业龙头 | 🤖 AI | Baostock 行业 + ths 主营 + 市值 | 判龙头地位：全球龙头100/国内90/A股最强80/Top3 50/不是0 |
| 5 | 市场辨识度 | 🤖 AI | 股票名 + ths 主营介绍 | 判「提到产品第一反应是它」=100，行业前三强品牌=90 等 |
| 6 | 个股风险值 | 🤖 AI | 新闻（em） | 识别减持/定增/官司/制裁/事故/造假，红线（叛国/违禁）触发一票否决 invalidate |

**两个关键设计**：

- **维度 3 是唯一纯算法维度**——不调 AI，confidence 恒为 1.0。这就是为什么网络/AI 全挂时它仍能出真分。
- **数据拉取和 AI 评分分离**：`data_provider.py` 先一次性拉全量数据（主营/新闻/行业/K线/成交额），再分发给 6 个维度评分器。某个数据源挂了，只影响依赖它的维度，不拖垮整体。

数据来源代码：`src/core/benzong/data_provider.py`。

| 数据 | 源 | 状态 |
|------|----|------|
| 行业归属 | Baostock `query_stock_industry` | ✅ 稳定 |

## 四、降级策略（不编造数据）

评分器的硬约束：**拿不到数据 / AI 失败时，绝不编造分数**。规则见 `src/core/benzong/dimensions/__init__.py`：

| 情况 | 返回 | 含义 |
|------|------|------|
| 数据缺失 | score=50（中性）, confidence=0, + warning | 不假装算出来 |
| AI 调用失败 | score=50, confidence=0, + warning | 同上 |
| 风险维度无新闻 | score=0, confidence=0.3 | 无新闻≠无风险，但无证据，低置信 |
| 风险维度红线 | score=100, invalidate=True | 一票否决，强烈建议放弃 |

**整体置信度 = 6 维 confidence 的最小值**。任何一维降级，整体置信度就被拉低，CLI 会显示 `⚠ 偏低（有维度数据缺失/AI 降级）`。这让用户一眼看出「这个分能不能信」。

## 五、缓存机制

缓存键：`(stock_code, date, dimension)`——同股同日同维度只算一次 AI。

- 存储：`~/.muyun/benzong_cache/`（文件缓存）
- 代码：`src/core/benzong/cache.py`
- **只缓存成功结果**（confidence > 0 才写缓存），避免缓存「失败降级」结果
- 改了维度评分器 prompt 后必须 `bz <code> --refresh` 才能看到新结果

## 六、命令用法

```
bz <代码>             笨总 AI 自动 6 维评分（默认，每维度调 1 次 AI，约 30-60s）
bz <代码> --refresh   强制刷新（跳过缓存）
bz --manual           旧交互式手动打分（v0.8.6.1 兜底，AI 全挂时用）
bz --check            数据源连通性体检（ISS-043，一键测全部源 + AI）
```

- 单股分析命令 `l <代码>` 末尾也会追加笨总评分摘要（缓存优先不重算）。
- `bz --check` 在网络异常时自检定位「哪个源挂了」，开发时调源前先跑它验证前提。

## 七、输出解读

跑 `bz 600989` 会输出（2026-06-20 真实实测）：

```
  ⚠ 1️⃣ 行业景气度 [conf 0.60] =  50.0 分
  ✓ 2️⃣ 业务纯度   [conf 0.95] = 100.0 分
  ✓ 3️⃣ 历史估值位置 [conf 1.00] =  64.7 分   ← 纯算法，恒高置信
  ✓ 4️⃣ 细分行业龙头 [conf 0.85] =  80.0 分
  ✓ 5️⃣ 市场辨识度 [conf 0.80] =  70.0 分
  ⚠ 6️⃣ 个股风险值 [conf 0.30] =   0.0 分     ← 新闻源挂，降级兜底

  💯 总分：110.61 → A 级
  🎯 总体置信度：0.30  ⚠ 偏低（有维度数据缺失/AI 降级）
  💾 缓存命中：0/6 维度
```

解读要点：
- **`✓`/`⚠` 标记**：✓ = 该维出真实分；⚠ = 降级（数据缺失或 AI 失败），分不可信
- **confidence**：0-1，该维分数可信度。纯算法维恒 1.0
- **总体置信度 = 6 维最低值**：0.30 说明至少一维降级了（本例是风险维新闻挂）
- **评分归一化到 0-100**（ISS-047；v0.8.7.6 B16 修复口径）：展示统一用 `normalized_score()` = 原始 / (正权和1.2×当期流动性系数)。满分 6 维在任何流动性下都恒等于 100，同一股票分数不随当日成交额漂移、跨日可比（原 ÷1.44 固定分母只在流动性系数 1.2 时成立，属刻度漂移 bug）
- **等级用 `effective_grade()`（含景气度闸门）**：若行业景气度 ≤30，实际等级会被压到 C 并标注「原 A」+ 景气分标红（见 §二）。别只看"A 级"就买——先看景气度这一维是不是真高
- **缓存命中 N/6**：命中数高说明是缓存的旧结果，`--refresh` 可强制重算

## 九、已知限制

1. **~~新闻源 SSL 问题~~**（v0.8.6.3 已修复）：`stock_news_em` 曾报 curl 77（中文路径致 curl_cffi 找不到 CA 证书）。已修复：certifi 证书复制到 ASCII 路径 + 设 `CURL_CA_BUNDLE`，data_provider/news_client 共用 `fix_curl_ssl_paths`。跑 `bz --check` 可验证 news 源状态。
2. **真实性判定难**：四要素中「真实性 = 一票否决」对 AI 极难（AI 不能上网交叉验证）。当前 MVP 阶段 AI 只在 prompt 里提示考量四要素，不真正一票否决，由用户最终确认。完整的四要素结构化判定器是 ISS-041 的 events 子任务。
3. **业务纯度靠 AI 解析文本**：A 股财报披露不规范，主营占比靠 AI 解析公司介绍可能误差大，需人工抽样校验。
4. **行业景气度偏主观，且撞 AI 能力天花板**（ISS-047）：当前只喂 AI「行业名 + 30 天新闻标题（≤10条）」，缺钢价/产能/库存/政策落地等关键数据，且是单次快照无时间序列——**分不清"该拿住的回调"和"行业真在死"**。换更强模型（如 V4 Pro）也解决不了，这是数据供给问题不是模型智商问题。`effective_grade()` 景气度闸门（§二）是当前的缓解手段，真正治本需接入更多行业基本面数据源。
5. **`bz scan` 双通道选股**（ISS-047）：`bz scan <主题词>` 用两个通道合并去重——通道A 法C（AI 报股，覆盖 PBO树脂等同花顺无板块的细分材料）+ 通道B 全市场客观筛选（复用 `quick_scan(market_query=)` 走同花顺行业/概念成分股，含中小盘非龙头）。修复了原先「AI 提示词只报龙头」的偏向。残留局限：同花顺成分股每板块上限 160 只（超大行业尾部漏）；极细材料同花顺无板块，仍靠法C 兜底。
