## 一、系统概述

### 1.1 定位

暮云思辨投资助手是一款**A股技术分析辅助决策工具**，基于规则引擎 + AI调节层，将用户的投资策略库（55章TXT文件）转化为可执行的量化规则，输出 BUY/SELL/HOLD/WATCH 决策及仓位管理建议。

**核心定位：** 研究与回测框架 + 决策辅助工具，**非实盘交易系统**。

### 1.2 技术栈

| 层级 | 技术 |
|------|------|
| 语言 | Python 3.11+ |
| 环境管理 | uv 虚拟环境 |
| 数据验证 | Pydantic v2 |
| 数据源 | Baostock v0.9.1（主）/ AKShare（备用 + 新闻源） |
| 规则引擎 | YAML + 自定义条件注册表 |
| AI调用 | OpenAI SDK v1.0+（兼容DeepSeek/Kimi） |
| CLI界面 | Rich |
| 统计计算 | NumPy |

### 1.3 六层架构总览

系统从 v0.8.0 起升级为**六层架构**，从"交易行为约束系统"升级为"信息驱动系统"：

```
CLI Layer (main.py)
    │
    ▼
┌─────────────────────────────────────────────────┐
│                  Orchestrator                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐   │
│  │ Data     │→ │ Signal   │→ │ Decision     │   │
│  │ Layer    │  │ Layer    │  │ Layer        │   │
│  │          │  │(Skill    │  │(信号聚合器)   │   │
│  │ 数据获取 │  │ Engine)  │  │              │   │
│  └──────────┘  └──────────┘  └──────┬───────┘   │
│                                      │           │
│                    ┌─────────────┐    │           │
│                    │ AI Modifier │←───┘           │
│                    │ Layer ⭐NEW │                │
│                    │(新闻+情绪)  │                │
│                    └──────┬──────┘                │
│                           │                       │
│  ┌──────────────┐  ┌─────┴─────────┐             │
│  │ Execution    │← │ Strategy      │             │
│  │ Layer        │  │ Layer         │             │
│  │ (现实约束)    │  │ (行为约束)     │             │
│  └──────────────┘  └──────────────┘              │
└─────────────────────────────────────────────────┘
```

**v0.8.0 核心升级**：在 Decision Layer 和 Strategy Layer 之间插入 AI Modifier Layer（新闻→情绪→三层信号调节），AI只负责信息理解/情绪判断/事件解析，不负责决策输出/交易执行。

## 二、数据模型

### 2.1 StockData — 输入数据结构

系统接收一个完整的 `StockData` 对象作为分析输入，包含以下字段组：

| 字段组 | 字段 | 说明 |
|--------|------|------|
| **基础** | stock_code, stock_name, price | 股票代码、名称、当前价 |
| **价格** | open, high, low | 开盘价、最高价、最低价 |
| **均线** | ma5, ma10, ma20, ma60, ma120, ma200 | 各周期移动平均线 |
| **成交量** | volume, avg_volume_5, avg_volume_20 | 当前成交量、均量 |
| **位置** | change_pct, high_60d, low_60d, high_120d, low_120d | 涨跌幅、N日高低点 |
| **MACD** | macd_dif, macd_dea, macd_hist | DIF线、DEA线、柱状图 |
| **RSI** | rsi_6, rsi_12, rsi_24 | 6/12/24日RSI |
| **布林带** | boll_upper, boll_mid, boll_lower | 上轨、中轨、下轨 |
| **KDJ** | kdj_k, kdj_d, kdj_j | K/D/J值 |
| **多时间框架** | monthly, weekly | 月线/周线数据（预留字段，当前仅用日线模拟） |
| **大盘** | index_trend, index_ma20/60/250, index_close, index_change_pct, index_high_250d | 沪深300指数趋势数据 |

> 所有技术指标和大盘数据字段均为 `Optional[float]`，允许缺失（降级分析）。

### 2.2 v0.7.2 新增模型

#### TradeLifecycle（交易生命周期枚举）

```
FLAT → OPEN → HOLD → EXIT → COOLDOWN → FLAT
```

| 状态 | 含义 | 转换条件 |
|------|------|----------|
| FLAT | 空仓 | 默认状态，或冷却结束 |
| OPEN | 新开仓 | FLAT+BUY 信号 |
| HOLD | 持仓中 | OPEN/HOLD 持续持仓 |
| EXIT | 退出过程 | REDUCE/CLOSE_ALL |
| COOLDOWN | 冷却期 | 清仓后限制期内禁止买入 |

#### StrategyState（策略状态）

| 字段 | 类型 | 说明 |
|------|------|------|
| lifecycle | TradeLifecycle | 当前生命周期阶段 |
| entry_date | Optional[str] | 开仓日期 |
| entry_price | Optional[float] | 开仓均价 |
| current_position_ratio | float | 当前仓位比例(0-1) |
| recent_signals | list[str] | 最近5日信号序列 |
| signal_stability_score | float | 信号稳定性评分(0-1) |
| inertia_counter | int | 当前决策已持续天数 |
| last_decision | Optional[SignalType] | 上一日最终决策 |
| cooldown_remaining | int | 冷却期剩余天数 |
| cooldown_reason | Optional[str] | 冷却原因 |
| reverse_count | int | 方向反转次数 |
| total_commission_paid | float | 已支付总佣金 |
| reduce_protection_remaining | int | 减仓保护期剩余天数 |

#### ExecutionConstraint（执行约束配置）

| 字段 | 默认值 | 说明 |
|------|--------|------|
| slippage_pct | 0.001 | 基础滑点 |
| volatility_slippage | True | 启用波动率滑点 |
| min_volume_ratio | 0.3 | 最低成交量比率（低于此值拒绝交易） |
| limit_up_blocked | True | 涨停禁止买入 |
| limit_down_blocked | True | 跌停禁止卖出 |
| impact_cost_enabled | True | 启用冲击成本 |
| impact_cost_rate | 0.001 | 冲击成本比率 |

### 2.3 信号与决策模型

六层架构下的完整数据流：

```
StockData → [13个技能] → SkillSignal[] 
         → DecisionEngine → DecisionResult 
         → AIModifier → AIModifierResult  ⭐v0.8.0
         → StrategyLayer → StrategyDecision 
         → ExecutionLayer → ExecutionEvaluation
```

**SkillSignal（技能信号）**：
- `signal`: BUY / SELL / HOLD / WATCH
- `confidence`: 0.0 ~ 1.0（置信度）
- `skill_type`: base / regulator / action（技能分类）
- `reason`: 判断理由列表

**DecisionResult（决策层输出）**：
- `decision`: 聚合信号（BUY/SELL/HOLD/WATCH）
- `state`: 市场状态（RISK_ON/RISK_OFF/TRANSITION/PANIC）
- `score`: 综合评分（0~1）
- `position_action`: 仓位动作（OPEN/ADD/REDUCE/CLOSE_ALL/HOLD_POSITION/STAY_OUT）
- `position_ratio`: 目标仓位比例（0~1）
- `trace`: 决策追溯路径（6步）
- `warnings`: 风险提示列表

**StrategyDecision（策略层输出，v0.7.2新增）**：
- `decision`: 经策略层过滤后的最终信号
- `position_action`: 经策略层计算的仓位动作
- `position_ratio`: 经策略层计算的目标仓位
- `lifecycle_before/after`: 生命周期转换
- `inertia_applied`: 是否应用了决策惯性
- `confirmation_required`: 是否需要信号确认
- `cooldown_blocked`: 冷却期是否阻止了交易
- `reverse_cost_paid`: 反转成本
- `stability_adjusted`: 稳定性是否调整了信号
- `new_state` (StrategyState): 更新后的策略状态
- `strategy_reasons` (list[str]): 策略层判断理由

**ExecutionEvaluation（执行层输出，v0.7.2新增）**：
- `executable`: 是否可执行
- `blocked_by`: 阻塞原因（liquidity/limit_up/limit_down/impact_cost）
- `slippage_pct`: 实际滑点
- `impact_cost_pct`: 冲击成本
- `estimated_price`: 预估成交价

**AIModifierResult（AI调节层输出，v0.8.0新增）**：
- `sentiment`: 市场情绪（bullish/bearish/neutral）
- `confidence`: AI判断置信度（0~1）
- `risk_level`: 风险等级（low/medium/high）
- `narrative_shift`: 叙事是否发生转变
- `event_type`: 事件类型（policy/war/earnings/macro/black_swan/none）
- `summary`: AI分析摘要
- `key_events`: 关键事件列表
- `source_count`: 新闻源数量
- `adjusted`: 是否对信号进行了调节
- `score_adjustment`: 评分调节值（负值=压制BUY）
- `position_cap`: 仓位上限（1.0=不调节，0.7=高风险打7折）
- `force_state`: 强制切换的市场状态（如PANIC，None=不干预）

## 三、技能引擎（规则层）

### 3.1 架构设计

系统采用 **YAML声明式规则 + 条件注册表** 架构：

```
YAML技能文件  →  SkillEngine加载  →  条件注册表匹配  →  SkillSignal输出
```

**设计原则**：
- 策略规则与代码解耦：业务规则写在YAML，代码只提供条件评估函数
- 条件注册表模式：所有可评估的条件以 `(name, evaluator)` 形式注册，YAML通过名称引用
- 参数化条件：YAML中可传参（如 `{ma: "ma20", pct: 1}`），实现条件复用

### 3.2 条件注册表（40+ 条件函数）

| 分类 | 条件名 | 说明 |
|------|--------|------|
| **均线** | price_above_ma, price_below_ma, ma_cross, ma_distance | 支持任意MA周期 |
| **涨跌幅** | change_positive, change_negative, change_range | 支持 min/max 阈值 |
| **成交量** | volume_above_avg, volume_below_avg, volume_ratio | 量比计算 |
| **位置** | price_near_high, price_near_low, price_position | N日高低点附近 |
| **MACD** | macd_dif_above/below_dea, macd_dif_above/below_zero, macd_hist_positive/negative | 金叉/死叉/零轴 |
| **RSI** | rsi_above, rsi_below | 支持6/12/24日，自定义阈值 |
| **布林带** | price_above/below/near_boll_upper/lower, boll_width_narrow/expand | 突破/收口/扩张 |
| **KDJ** | kdj_k_above/below_d, kdj_j_above/below | 金叉/死叉/超买超卖 |
| **大盘** | index_bullish, index_bearish, index_neutral | 沪深300趋势 |

### 3.3 规则评估逻辑

单个技能内多条规则的聚合方式：

1. **逐条评估**：遍历YAML中的每条rule，调用条件注册表匹配
2. **条件满足判定**：一个condition块内有多个条件时，满足 ≥ 50% 即算命中
3. **信号聚合**：命中规则中 BUY 数 > SELL 数 → BUY，反之 SELL，相等 → HOLD
4. **置信度计算**：加权平均 `Σ(confidence×weight) / Σweight`，上限1.0
5. **无命中规则**：默认输出 WATCH，confidence=0.3

### 4.1 完整六层决策流水线

```
┌─────────────────────────────────────────────────────────┐

┌─────────────────────────────────────────────────────────┐

│   base(8) + regulator(3) + action(2)                    │

                     ↓
┌─────────────────────────────────────────────────────────┐

                     ↓
┌─────────────────────────────────────────────────────────┐

│   新闻抓取 → AI分析 → 情绪/风险/事件识别 → 三层调节        │
│   Layer 1: 信号调节 (bearish压制BUY, bullish轻微增强)     │

                     ↓

│ Strategy Layer (v0.7.2 核心新增):                         │
│   惯性 → 确认 → 冷却 → 反转成本 → 稳定性 → 极端行情感知   │

└────────────────────┬────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────────────┐

│   流动性 → 涨跌停 → 波动率滑点 → 冲击成本                  │

```

### 4.2 决策层（Decision Layer）— 信号聚合

#### 第一步：市场状态判定（StateMachine）

基于**沪深300年线（250日均线）**的A股行业标准方法：

| 状态 | 判定条件 | 变化频率 |
|------|----------|----------|
| **RISK_ON** | 沪深300 > 年线 且 回撤 < 15% | 数周到数月 |
| **RISK_OFF** | 沪深300 < 年线 且 回撤 > 20% | 数周到数月 |
| **TRANSITION** | 年线附近(±3%) 或 回撤15%~20% | — |
| **PANIC** | 当日跌>5% 或 跌破MA60+放量暴跌 | 即时 |

**优先级**：PANIC > 年线判断 > MA20/MA60降级 > 个股均线降级

**设计选择**：为什么用年线而非5维度评分？
- 旧方案用5维度（含当日涨跌+成交量）打分，状态1~2天就翻转
- 年线是A股30年共识的牛熊分界线，变化频率数周到数月，更稳定

#### 第二步：基础信号投票（base技能）

只看 `skill_type=base` 的8个技能信号：

```
各信号得分 = confidence × weight（权重来自配置）
归一化：各信号得分 / 总权重
```

权重配置（settings.yaml）：

| 技能 | 权重 | 类型 | 说明 |
|------|------|------|------|
| ma_trend | 1.0 | base | 均线趋势 |
| volume_price | 1.0 | base | 量价验证 |
| support_resistance | 1.0 | base | 支撑阻力 |
| multi_timeframe | 1.2 | base | 多周期（权重略高） |
| macd | 1.0 | base | MACD |
| rsi | 0.8 | base | RSI（权重略低，容易超买超卖） |
| boll | 0.9 | base | 布林带 |
| kdj | 0.8 | base | KDJ（权重略低，短期噪音大） |
| position_context | 1.3 | regulator | 位置上下文 |
| market_context | 1.5 | regulator | 大盘环境 |
| smart_money | 1.2 | regulator | 主力行为 |
| stop_loss | 1.5 | action | 止损管理 |
| take_profit | 1.3 | action | 止盈管理 |

#### 第三步：上下文调节器修正（regulator技能）

3个regulator技能不产出独立信号，而是**修改base得分**：

| regulator信号 | 对BUY得分 | 对SELL得分 |
|---------------|-----------|------------|
| SELL | ×(1-impact) 降低 | ×(1+impact) 提高 |
| BUY | ×(1+impact) 提高 | ×(1-impact) 降低 |
| WATCH | ×(1-impact×0.5) 轻微降低 | ×(1-impact×0.5) 轻微降低 |
| HOLD | 不调整 | 不调整 |

其中 `impact = 0.5 + (weight - 1.0) × 0.2`，上限0.8。多个regulator的修正系数取**几何平均**。

#### 第四步：SELL分层门槛（市场状态依赖）

| 市场状态 | SELL门槛 | 策略含义 |
|----------|----------|----------|
| PANIC | 0.20 | 极端行情先跑再说 |
| RISK_OFF | 0.25 | 熊市灵敏卖出（该跑就跑） |
| TRANSITION | 0.30 | 震荡中等门槛 |
| RISK_ON | 0.35 | 牛市保守卖出（避免震荡洗出） |

**额外约束**：牛市中SELL还需满足 `sell_score > buy_score × 1.2`（强SELL判定），否则降为WATCH。

#### 第五步：动作信号覆盖（止损/止盈优先级）

**止损（stop_loss）— 一票否决（有仓位时）**：

| 情况 | 触发条件 | 结果 |
|------|----------|------|
| 有仓位 + 止损SELL ≥ 0.8 | confidence ≥ 0.8 | 直接覆盖为SELL |
| 空仓 + 止损SELL ≥ 0.8 | confidence ≥ 0.8 | BUY→WATCH，其他不变 |
| 空仓时止损不触发卖出 | — | 保护性观望，不放大空仓卖出 |

**止盈（take_profit）— 压制性覆盖**：

| 情况 | 触发条件 | 结果 |
|------|----------|------|
| 止盈SELL ≥ 0.75 + 当前BUY | confidence ≥ 0.75 | BUY→HOLD（压制买入） |
| 止盈SELL ≥ 0.75 + 当前HOLD | confidence ≥ 0.75 | HOLD→SELL（确认卖出） |

### 4.3 AI调节层（AI Modifier Layer）— v0.8.0 新增

#### 设计目标

技术面分析只看K线和成交量，无法感知新闻/政策/黑天鹅等现实事件。AI Modifier Layer 在 Decision Layer 之后、Strategy Layer 之前介入，用AI分析新闻情绪，对技术面信号进行微调。

**核心原则**：AI只负责信息理解/情绪判断/事件解析，**不负责决策输出/交易执行**。

实现路径：`src/core/ai_modifier.py` → `class AIModifier`

#### 新闻数据流

```
AIModifier.analyze(stock_data)
  ├── NewsClient.gather_news_for_analysis(stock_code)
  │   ├── get_stock_news() → AKShare stock_news_em() → 10条个股新闻
  │   └── get_macro_news() → AKShare stock_info_global_em() → 10条宏观快讯
  ├── NewsClient.format_news_for_ai() → 格式化文本（截断200字/条）
  ├── OpenAI SDK → 调用DeepSeek/Kimi API（temperature=0.1, max_tokens=500）
  └── _parse_response() → 解析JSON → AIModifierResult
```

#### 三层调节机制

AIModifierResult 产出后，`_apply_modification()` 原地修改result，Orchestrator将调节参数应用到后续流程：

**Layer 1 — 信号调节（score_adjustment）**：

| AI情绪 | 调节公式 | 效果 |
|--------|---------|------|
| bearish | score_adjustment = -(confidence × sentiment_weight) | 压制BUY信号 |
| bullish | score_adjustment = +(confidence × sentiment_weight × 0.3) | 轻微增强，权重打3折 |
| neutral | score_adjustment = 0 | 不调节 |

- sentiment_weight 默认 0.3（可配置）
- 叙事转变加强：narrative_shift + confidence > 0.5 → score_adjustment × 1.5

**Layer 2 — 仓位调节（position_cap）**：

| AI风险等级 | position_cap | 效果 |
|-----------|-------------|------|
| high | risk_position_cap（默认0.7） | 最多7成仓 |
| medium | (1.0 + risk_position_cap) / 2 ≈ 0.85 | 中间值 |
| low | 1.0 | 不调节 |

- 叙事转变加强：narrative_shift + confidence > 0.5 → position_cap × 0.85

**Layer 3 — 状态干预（force_state）**：

| AI事件类型 | 调节 | 效果 |
|-----------|------|------|
| black_swan | force_state = PANIC, position_cap = 0.3, score_adjustment = -0.5 | 强制恐慌 |
| 其他 | force_state = None | 不干预 |

#### Orchestrator中的应用

```python
# orchestrator.py 中的AI调节流程
if ai_enabled and self.ai_modifier and self.ai_modifier.is_available():
    ai_result = self.ai_modifier.analyze(stock_data)

    # Layer 1: 信号调节
    decision_result.score += ai_result.score_adjustment

    # Layer 2: 仓位调节
    decision_result.position_ratio *= ai_result.position_cap

    # Layer 3: 状态干预
    if ai_result.force_state:
        decision_result.state = ai_result.force_state
```

| 提供商 | base_url | 默认模型 | pro模型 |
|--------|---------|---------|--------|
| DeepSeek | https://api.deepseek.com | deepseek-v4-flash | deepseek-v4-pro |
| Kimi | https://api.moonshot.ai/v1 | moonshot-v1-auto | kimi-k2.6 |

- API Key优先级：`settings.yaml配置 > 环境变量(DEEPSEEK_API_KEY/KIMI_API_KEY)`
- 优雅降级：未配置API Key → `self.enabled = False` → `analyze()` 返回 neutral 空结果

#### 新闻缓存策略

| 数据类型 | 缓存 | TTL |
|---------|------|-----|
| 个股新闻 | 同会话同一股票只抓一次 | 会话级 |
| 宏观快讯 | 类属性缓存 | 1小时（可配置） |

#### AI系统提示词（SYSTEM_PROMPT）

要求AI严格按照JSON格式输出，包含7个字段：sentiment/confidence/risk_level/narrative_shift/event_type/summary/key_events。

核心原则：
- "宁可低估影响也不要夸大"（保守评估）
- "仅基于提供的新闻内容分析"（不幻觉）
- "confidence反映你对判断的把握程度"（诚实评估）

### 4.4 策略层（Strategy Layer）— v0.7.2 核心新增

#### 设计目标

Strategy Layer 的本质不是"分析"，而是：
- **约束行为** — 让决策符合交易规律，而非每日独立判断
- **延迟决策** — 避免对单日信号过度反应
- **抑制噪声** — 过滤短期波动干扰
- **维持一致性** — 保证方向连续，不频繁反转

实现路径：`src/core/strategy_layer.py` → `class StrategyLayer`

#### 机制一：交易生命周期状态机

系统显式建模完整交易周期：

```
        BUY
  FLAT ─────→ OPEN
   ↑            │持续持仓
   │            ↓
  COOLDOWN     HOLD
   ↑            │SELL
   │            ↓
   └───── EXIT (REDUCE/CLOSE_ALL)
```

状态机规则：

| 当前状态 | 信号 | 新状态 | 条件 |
|----------|------|--------|------|
| FLAT | BUY | OPEN | 无冷却期阻塞 |
| OPEN | BUY | HOLD | 已建仓 |
| HOLD | SELL | EXIT | 止损/止盈/减仓 |
| EXIT | — | COOLDOWN | 清仓后自动进入 |
| COOLDOWN | — | FLAT | 冷却天数归零 |

#### 机制二：决策惯性（Inertia）

防止持仓时被短期反向信号洗出：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| INERTIA_MIN_DAYS | 3 | 持仓至少3天后才允许方向反转 |
| INERTIA_BUY_THRESHOLD_BUMP | 0.10 | 持仓时SELL信号门槛提高0.10 |

**极端行情感知**：当系统自动检测到极端行情（单日跌幅>5%、涨幅>7%、触发强力止损）时：
- 惯性期从3天缩短为1天
- 止损跳过确认阶段
- 冷却期从5天缩短为2天

#### 机制三：信号确认（Confirmation）

单日信号不直接触发决策，必须连续出现或增强：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| CONFIRMATION_MIN_CONSECUTIVE | 2 | 信号连续出现至少2天 |
| CONFIRMATION_WEAK_SIGNAL_THRESHOLD | 0.30 | 弱信号(confidence<0.3)直接拦截 |

#### 机制四：冷却机制（Cooldown）

平仓后限制短期内反向操作，防止来回打脸：

| 场景 | 冷却天数 | 说明 |
|------|----------|------|
| 清仓后 | 5 | 区间内禁止买入 |
| 减仓后 | 10 | 同一原因不重复减仓 |

#### 机制五：反转成本（Reverse Cost）

每次反向操作需"付费"，成本与持仓时间和反转次数相关：

```
成本 = 0.3% + 反转次数 × 0.2%
若决策confidence不足以覆盖成本 → 降级为HOLD
```

#### 机制六：信号稳定性（Stability）

| 稳定性评分 | 处理方式 |
|-----------|----------|
| < 0.4（信号频繁变化） | confidence × 0.7 打折 |
| ≥ 0.4 | 正常处理 |

#### 仓位管理（整合在策略层中）

**仓位上限（按市场状态）**：

| 市场状态 | 最大仓位 | 策略依据 |
|----------|----------|----------|
| RISK_ON | 60% | 第17章：总仓位上限60% |
| TRANSITION | 30% | 分歧期轻仓 |
| RISK_OFF | 15% | 熊市极轻仓 |
| PANIC | 0% | 恐慌不持仓 |

**建仓/加仓规则**：

| 动作 | 比例 | 条件 |
|------|------|------|
| 试探建仓(OPEN) | 20% | 第53章"先买两成" |
| 加仓(ADD) | 加到40% | 趋势确认后加倍 |
| 弱买入建仓 | 10% | 信号弱时极轻仓 |

**减仓/清仓规则**：

| 场景 | 动作 | 逻辑 |
|------|------|------|
| 深度止损(confidence≥0.85) | CLOSE_ALL | 趋势走坏，全清 |
| 浅层止损(confidence<0.85) | REDUCE留65%底仓 | 短期走弱≠趋势反转 |
| 止盈 | REDUCE留60%底仓 | 第49章：分批止盈留底仓 |
| 仓位<5% | CLOSE_ALL | 仓位太小，交易成本不划算 |

**减仓保护期**：

| 原因 | 保护天数 | 说明 |
|------|----------|------|
| 深度止损 | 0 | 直接清仓，不保护 |
| 浅层止损 | 15 | 给市场恢复时间 |
| 止盈 | 10 | 等下一波 |
| 强卖出(score≥0.4) | 5 | 强信号可信度高 |
| 不同原因间 | 最少5天 | 避免频繁操作 |

### 4.5 执行层（Execution Layer）— v0.7.2 新增

#### 设计目标

将"理想交易"转为"可执行交易"，评估现实约束是否允许交易。

实现路径：`src/core/execution_layer.py` → `class ExecutionLayer`

#### 评估流程（4步）

```
Evalutate(data, position_action)
  ├── Step 1: 流动性检查（成交量 < avg×0.3 → 拒绝）
  ├── Step 2: 涨跌停检查（涨停不能买 / 跌停不能卖）
  ├── Step 3: 波动率滑点计算（滑点 = 0.1% + 波动率因子）
  └── Step 4: 冲击成本计算（与量比负相关）
```

| 约束 | 计算方式 | 默认阈值 |
|------|----------|----------|
| 流动性 | volume < avg_volume_20 × min_volume_ratio | 0.3 |
| 涨停 | change_pct ≥ 9.5% → 禁止买入 | — |
| 跌停 | change_pct ≤ -9.5% → 禁止卖出 | — |
| 滑点 | 0.001 + 波动率相关增量（用60日振幅近似） | 动态 |
| 冲击成本 | 0.001 × (1 - 量比归一化值) | — |

### 4.6 持仓管理（Portfolio Management）— v0.7.3 新增

#### 设计目标

系统需要记住持仓状态，以便策略层的生命周期/惯性/冷却等机制跨会话工作。

#### 设计方案

采用**YAML文件 + 自动建议 + Y/N确认**的半自动模式：

```
PortfolioManager
  ├── 读取 portfolio.yaml → 初始化 StrategyState
  ├── 分析后建议更新持仓 → 用户Y/N确认
  ├── 支持手动操作：add_position / remove_position / list_positions
  └── 数据持久化到 portfolio.yaml（已纳入版本控制）
```

**设计原则**：
- 持仓数据必须真实，系统只建议不强制
- YAML格式透明可编辑，用户随时手动修改
- 系统自动维护 `strategy_state`（冷却期/惯性/信号序列等），用户一般不需要碰
- 通过Git同步 `portfolio.yaml` 实现多设备持仓同步

**数据流**：

```
启动分析 → PortfolioManager读取持仓 → 初始化为StrategyState
       ↓

       ↓

                                  ↓

```

**lifecycle字段说明**：
| lifecycle | 含义 |
|-----------|------|
| FLAT | 空仓 |
| OPEN | 新开仓 |
| HOLD | 持仓中 |
| EXIT | 退出过程 |
| COOLDOWN | 冷却期 |

## 六、回测框架

### 6.1 回测流程

```
BacktestEngine.run()
  ├── DataFeeder.load()         # 加载历史数据
  ├── SimulatedAccount初始化     # 初始资金10万
  └── 逐日循环:
      ├── 执行前日挂单（次日开盘价）  ← 消除前视偏差
      ├── 生成今日信号（明日执行）    ← Orchestrator.analyze
      └── 记录每日快照
```

### 6.2 交易规则

| 规则 | 说明 |
|------|------|
| **前日信号+次日开盘价** | Day N-1收盘后分析→Day N开盘价执行，消除前视偏差 |
| **T+1硬限制** | 买入日必须严格早于卖出日（A股基本规则） |
| **最小持有天数** | 默认5天（含T+1），防止短线频繁交易 |
| **冷却期** | 清仓后5天内不再买入同一只股票 |
| **滑点** | 买入上浮0.1%，卖出下浮0.1% |

### 6.3 交易成本模型（A股标准）

| 费用项 | 买入 | 卖出 |
|--------|------|------|
| 券商佣金 | 0.025%（最低5元） | 0.025%（最低5元） |
| 印花税 | — | 0.05%（2023年减半后） |
| 过户费 | 0.001% | 0.001% |

### 6.4 仓位管理执行

| 仓位动作 | 执行逻辑 |
|----------|----------|
| OPEN | 无仓位时买入目标比例（默认20%），含滑点+费用 |
| ADD | 有仓位时追加买入到目标比例（加到40%） |
| REDUCE | 按目标仓位卖出差额股数；余量<100股全卖；减后<5%直接清仓 |
| CLOSE_ALL | 全部卖出，进入冷却期 |
| STAY_OUT | 不操作 |

**空仓保护**：无持仓时止损/止盈SELL覆盖不生效，回退到base信号判断。

### 6.5 Monte Carlo 回测（v0.7.2 新增）

同一策略在不同随机条件下的分布评估：

```
run_monte_carlo(n_simulations=100, seed=42)
  ├── 每次随机扰动：滑点、执行延迟、成交价格
  └── 输出结果分布而非单值
```

### 6.6 统计指标

| 指标 | 计算方式 |
|------|----------|
| 总资金收益率 | 最终资产/初始资金 - 1 |
| 投入资金收益率 | 盈利/实际投入成本（反映选股能力） |
| 年化收益率 | (最终/初始)^(1/年数) - 1 |
| 最大回撤 | max((peak - valley) / peak) |
| 夏普比率 | mean(日收益率) / std(日收益率) × √252 |
| 胜率 | 盈利交易次数/总交易次数 |
| 盈亏比 | 平均盈利/平均亏损 |
| 基准收益 | 买入持有收益率 |
| **最差收益（v0.7.2）** | Monte Carlo 最坏场景 |
| **回撤稳定性（v0.7.2）** | 回撤路径的波动程度 |
| **结果方差（v0.7.2）** | Monte Carlo 结果离散度 |
| **决策稳定性（v0.7.2）** | 每日决策的连续性评分 |

### 6.7 执行约束统计

回测结束后统计执行层阻塞情况（v0.7.2新增）：

| 统计项 | 说明 |
|--------|------|
| blocked_by_limit_up | 因涨停无法买入的次数 |
| blocked_by_limit_down | 因跌停无法卖出的次数 |
| blocked_by_liquidity | 因流动性不足拒绝交易的次数 |

### 9.3 回测可信度说明

回测结果**不代表未来收益**，需注意：
- **过拟合风险**：策略参数基于历史数据调优，未来市场结构可能变化
- **样本外测试建议**：用2023年数据调参，2024-2025年验证
- **关键指标门槛**：夏普>0.5，最大回撤<25%，胜率>40%
- **多股验证**：单只股票回测不足以说明策略有效性
- **Monte Carlo 辅助**：v0.7.2 引入的多场景随机测试可提供更稳健的评估

```

Step 4: 调节器修正
  → modifiers: ["BUY: ×1.150", "SELL: ×0.850"]
  → adjusted_scores: {BUY: 0.40, SELL: 0.10, ...}

Step 5: 市场状态影响
  → 状态=RISK_ON, 决策前信号=BUY

Step 6: 动作信号覆盖
  → 止损/止盈优先级检查 → 未覆盖
  → 决策层输出: BUY (score: 0.40)
  ↓

  → AI情绪: bearish (confidence: 0.6)
  → score_adjustment: -0.18 (= -0.6 × 0.3)

  → 调节后: BUY (score: 0.22), position_ratio × 0.85
  ↓

  ↓
Step 9: 执行层评估（v0.7.2+）
  → 流动性检查: 通过
  → 涨跌停检查: 未触及
  → 滑点: 0.15%
  → 结果: 可执行 ✓
```
