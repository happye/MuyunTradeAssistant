## 二、重构总纪律（违反任何一条 = 停手）

1. **功能不变是硬约束**。行为不变的证明 = 全量测试数字守恒 + CLI 输出零变化。
2. **测试断言不得修改来适配重构**。改断言 = 可能在偷偷改行为；确因等价重构必须动断言时，
   逐条写论证并放进 commit message。
3. **重构与行为变更严禁混提交**（AGENTS §二·五 明文：重构 commit 必须注明
   「内部重构无行为变化」+ 范围）。发现问题想顺手修？记进 ISSUES，另开 commit。
4. 每完成一个独立单元（文件/类/函数群）→ 单独 commit → 全量测试。
5. **logger 文案是接口**：任何 warning 文案被 plain_errors.WARNING_PATTERNS 子串匹配
   （src/cli/plain_errors.py）+ docs/报错速查手册.md 构成三处同步义务——重构尽量不碰文案。
6. 本会话实证：两次独立监督审查共抓出 **5 个实现者自己漏掉的缺陷**
   （chat 回写抹 TradePlan、confirm 门三洞、matched_via 误标、L2/L3 零覆盖、
   90s 超时预算错配）。重构收尾强烈建议同样请一位独立审查代理，重点查
   「分支覆盖」（每个 if/elif 分支至少一条测试路径）与「mock 与真实行为脱节」。

## 四、重构时必看的脆弱耦合（改 A 会炸 B）

1. **rich Console 动态解析 sys.stdout**：chat 的 Tee 输出捕获依赖 main.py 的 console
   未固定 file 参数——重构时给 Console 传 file = chat 命令回显静默失效。
2. **plain_errors 子串匹配**（见上）。
3. **industry_data 文本协议**：「[数据缺失]/[数据缺口]/[数据过期]」前缀被
   _cached 的 TTL 分支（失败只缓存 5 分钟）与 industry_prosperity._is_missing 等
   多处 startswith 判断——这些字符串是协议不是文案。
4. **portfolio.yaml 键协议**：G04 zfill(6) 规范化、trade_plan 整体回写链
   （ISS-078 P0 刚修：重建记录必须从 existing 全量携带）。
5. **session_state / #N 引用**：chat 与 REPL 共享 ~/.muyun/last_scan.json 文件协议。
6. **RAG 索引**：fingerprint 是 mtime 机制（非内容哈希），embedder_metadata 兼容旧索引。
7. **configs/industry_chains*.yaml**：手写链的 commodity/demand_data 绑定字段是
   bz 景气度接线（ISS-083）的数据通道；match_chain 新增的 `chains` 参数有调用方。
8. **YAML↔代码硬编码**：healthy_pullback 14 处；settings.yaml 的
   ai.request_timeout/max_retries 有读者（v0.8.8.6 刚显式化）。
