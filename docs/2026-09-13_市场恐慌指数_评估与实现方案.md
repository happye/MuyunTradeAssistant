# 市场恐慌指数（Fear Index）— 评估与实现方案

> 2026-09-13 立项评估稿。状态：**待用户拍板，未实施**。
> 需求：给项目加一个「市场恐慌指数」，可精确到概念/板块/个股，可单查可一键总览，数据必须真实无污染；既做成 REPL 命令，也做成 chat agent 可自动调用的工具；高可扩展。

---

## 一、需求还原与设计原则

**用户原话拆解成 5 条硬要求：**

1. **下钻能力**：不止全市场一个数——要能查「某个概念」「某个板块」「某只股票」的恐慌度。
2. **一键总览**：一条命令看全局 + 关键局部。
3. **数据真实**：真实数据源、准确无误、无污染。
4. **双入口**：REPL 命令 + chat agent 工具（agent 能自己决定何时调用）。
5. **高可扩展**：指标可加、权重可调、范围可扩。

**由第 3 条推导出的 4 条设计原则（本方案的根基）：**

- **P-纯客观**：指数计算层 **AI 调用次数 = 0**。AI 只负责「解读已算出的数字」，永远不参与算分。——这是 ISS-083 的直接教训（景气度维从「AI 猜」改为「客观数据主导」），AI 在数据缺失时会脑补，与"无污染"根本冲突。
- **P-显式降级**：任何子指标数据缺失/超时/熔断 → 该指标标 `MISSING`，聚合时**剔除权重并显式展示**「缺了什么」，绝不 fallback 到假数据或默认分。
- **P-可溯源**：输出里每个成分标注「原始值 + 数据源 + 数据时间戳 + 状态」，用户能看见每个数从哪来。
- **P-回测禁网**：回测路径只读本地历史快照库，绝不实时拉网（ISS-063 宏观层门控同款纪律）。

**与市面产品的核心差异定位**：市面所有恐慌/情绪指数（乐咕、韭研、研报系）都只做到**全市场一个数**。本方案的核心增量是**同一套指标引擎跑在不同 scope 上**——全市场、板块、概念、个股用同一框架计算，这才满足"精确到某个概念/某个板块/某个股票"的需求。

### 3.1 指数语义定义（先说清楚，避免歧义）

**输出 0-100，越高越恐慌**（用户要的是「恐慌指数」，与 CNN 的"贪婪指数"方向相反，内部计算按恐慌方向归一）：

| 区间 | 档位 | 展示色 |
|---|---|---|
| 0-20 | 极度贪婪 | 红（反向指标警示） |
| 20-40 | 贪婪 | 黄 |
| 40-60 | 中性 | 白 |
| 60-80 | 恐慌 | 蓝 |
| 80-100 | 极度恐慌 | 亮蓝 |

### 3.2 scope 体系（下钻的核心）

```
fear                  → scope=market
fear 科技             → 主题词 → 复用 scanner 主题模糊匹配 → 行业∪概念成分集
fear 半导体           → 行业名
fear 氮化镓           → 概念名
fear 600519           → 个股（自动带出所属板块做对照）
```

- L0 `market`：全市场口径。
- L1 `sector`：行业/概念成分股集合口径 —— **关键成本设计**：成分过滤在 `MarketCache.get_all_stocks()` 全市场快照上本地完成（快照含涨跌幅/成交额/换手率/量比/振幅），**0 新增网络请求**；趋势/波动维度用东财板块指数日线（1 请求/板块，日缓存）；打板维度用涨停池接口结果按成分过滤（0 新增）。
- L2 `stock`：个股口径，所有指标都是"个股相对自身历史/所属板块"的相对量，单一股票单独谈恐慌无意义。

### 3.3 归一化双模式（历史不足时如何保真）

每个子指标声明 `normalizer: percentile | threshold`：

- **percentile**（首选）：当日值在自身近 N=250 交易日序列里的分位。历史序列从本地快照库读。
- **threshold**（兜底）：固定阈值映射（CNN 式，如 涨跌家数比 0.3→95 分、0.5→50 分、0.7→5 分）。
- **自动降级**：历史样本 < 60 日时自动用 threshold，并在输出标注「分位样本不足(37/250)，暂用固定阈值口径」——**宁可标注不完美，不可静默混口径**。
- 上线时做一次**历史回填**：涨停池/指数日线/成交额/两融/国债利率都支持按历史日期回拉，可回填 250 日（涨停池按日拉约 250 次请求，节流下约 5-8 分钟，一次性成本，可放后台任务）；涨跌家数比**不可回填**（新浪快照只有当日），该成分上线初期走 threshold 口径，随快照积累自动切 percentile。

### 3.4 聚合与质量标记

```
总分 = Σ(可用成分得分 × 权重) / Σ(可用成分权重)     # 缺失成分剔除权重，不是补 50
输出附带：每个成分 {原始值, 得分, 状态: OK|STALE|MISSING, 数据源, 数据时间}
样本数不足的成分（如板块成分股 < 10 只）整级降为 MISSING
```

## 四、子指标清单 v1

### L0 全市场（7 成分，参考 CNN 框架 + A 股特色）

| # | 成分 | 口径 | 数据源 | 归一化 | 新增请求 |
|---|---|---|---|---|---|
| 1 | 涨跌广度 | 上涨家数 / (上涨+下跌) | 全市场快照（已有） | percentile（不可回填，先 threshold） | 0 |
| 2 | 打板热度 | 涨停家数、跌停家数、**炸板率** 三合一子分 | 东财涨停池×3 | percentile（可回填） | 日缓存后 0 |
| 3 | 市场波动 | 沪深300 20日已实现波动率（替代 VIX；QVIX 官方已停发） | 指数日线（已有） | percentile（可回填） | 0 |
| 4 | 市场动量 | 沪深300 现价 vs MA125 乖离 | `_get_index_trend`（已有） | threshold | 0 |
| 5 | 成交热度 | 两市成交额 5日均 vs 250日分位 | `get_market_turnover`（已有） | percentile（可回填） | 0 |
| 6 | 杠杆情绪 | 融资余额 5日变化率（方向：加杠杆=贪婪） | 两融明细（已有 memo） | percentile（可回填） | 日缓存后 0 |
| 7 | 股债性价比 | 每日盈利收益率（盈利用乐咕 PE 采样点反推阶梯，point-in-time；价格用 baostock 日频）− 10Y国债，自算日频（乐咕/中证 PE 历史均为稀疏采样不够分位窗，实施探针后定稿自算口径） | 乐咕PE + baostock + 10Y（已有） | percentile（可回填） | TTL 后 0 |

**成分方向口径定稿（自查补充，2026-09-13）**——每个成分统一换算为「越高越恐慌」，歧义项的处理：

- **炸板率定义**：炸板家数 /（涨停收板家数 + 炸板家数），高=封板承接弱=恐慌。
- **涨停家数只展示、不进聚合**：涨停多既可能是贪婪狂热也可能是行情启动，方向歧义，进分会污染指数；跌停家数、炸板率方向明确，进聚合。涨停/跌停家数在总览中作为独立展示行。
- **成交热度用 U 型映射**：成交额分位 <10%（冰点=流动性恐慌）或 >95%（天量=情绪极端）都贡献高恐慌分，中间区间线性回落至中性——两端才是情绪信号，中间无方向。
- **股债利差方向**：利差（股息率−10Y国债）越大=股价被恐慌砸得越便宜，利差高分位=高恐慌分。
- **动量乖离阈值映射（threshold）**：价/MA125 乖离 ≥+15% → 5 分（极度贪婪端）；+5% → 25；±5% → 50；−5% → 75；≤−15% → 95，中间线性插值。

### v2+ 候选（明确不进 v1，原因写明）

- **期权 PCR**：`option_current_em` 自算沽购持仓比——A股最接近 VIX 的源，但接口稳定性未探针，**探针通过后 P2 收编**。
- **连板高度/晋级率（1进2）**：短线情绪拐点最敏感指标，涨停池数据已有，P3 加（需连板梯队解析逻辑）。
- **北向资金**：2024-08 起停发盘中实时数据，可得性差，**不做**。
- **新高新低家数**：需全市场 52 周高低点，成本高收益低，缓做。
- **乐咕市场活跃度** `stock_market_activity_legu`：已确认接口存在，返回字段需探针；若好用可作成分 1 的**交叉验证源**（双源一致性校验，正合"准确无误"诉求）。

## 五、数据真实性与防污染设计（七条军规）

1. **计算层零 AI**：`src/core/fear_index/` 内不 import 任何 AI client；chat agent 拿到结构化结果后自己解读，chat 系统提示加条款「fear 结果只许引用返回字段，MISSING 就是缺失，禁止脑补」。
2. **成分级溯源**：输出每个成分带 `{原始值, 数据源标签, 数据时间戳, 状态}`，总览底部显示「数据基准时刻」。
3. **质量门**：快照样本 < 100 只 → 广度成分 MISSING（复用 `assess_market_breadth` 的阈值经验）；板块成分股 < 10 只 → 整个 L1 降级为 MISSING + 提示。
4. **显式降级**：源失败 → `STALE`（用当日早前缓存并标注时间）或 `MISSING`，绝不静默。
5. **快照质量校验**：复用 `MarketCache._snapshot_quality_ok` 思路，入库前校验行数/字段完整性。
6. **公式锁死**：归一化/聚合写单元测试锁口径（对齐 DataFeeder 等价性测试的纪律），改口径必须 bump `FEAR_CACHE_VERSION`。
7. **回测隔离**：`get_fear_report(scope, as_of_date=...)` 支持按历史日期从快照库取数；回测调用绝无网络路径（结构上与 benzong 景气度回测隔离同款）。

## 六、命令与 chat 工具设计

### 6.1 REPL 命令

```
fear                    # 一键总览：总分面板 + 7成分明细(原始值/得分/来源/状态) + 近30日走势
                        #   + 持仓股所属板块自动下钻小表（P2）
fear 科技               # 主题词/行业/概念下钻（复用 scanner 主题模糊匹配，含 AI 纠偏）
fear 600519             # 个股情绪温度 + 所属板块对照（P3）
fear history            # 多周期回顾：近5日/10日/1个月/3个月 摘要表+趋势判断
                        #   + 生成走势图保存到本地（见 6.4，P1 范围，market 级）
fear history --no-chart # 只输出文字摘要，不生成图片
fear --refresh          # 强刷当日缓存
fear backfill [--days 250]  # 涨停池历史回填（显式触发，进度条+断点续传，详见 6.5）
```

- 缓存：当日口径复用 17:30 灰区 + 盘中 TTL 10 分钟模式（`is_trading_hours` 已有）；盘中每次调用全成本 ≈ 涨停池 3 请求 + 板块指数 1 请求，当日缓存命中后 0 请求。
- 渲染：Rich Table/Panel，参照 `expect` 的 `show_expect`（分档着色面板 + 倒计时列的成熟范式）。

### 6.2 chat 工具

```json
{ "name": "get_fear_index",
  "description": "获取市场/板块/概念/个股恐慌指数(0-100,越高越恐慌)及成分明细",
  "parameters": { "scope": "string(默认 market，支持主题词/行业/概念/代码)",
                  "include_components": "boolean(默认 true)" } }
```

- 返回结构化 dict（总分+档位+成分数组+质量标记+数据基准时刻），agent 自行解读。
- 注册三件套：`TOOL_REGISTRY` + schema + 系统提示（与 search_knowledge 同链路）。
- `history_windows` 参数（默认 `[5,10,22,66]`）：返回各周期摘要 dict + `chart_path`（图片照常生成存本地，供用户打开；agent 只转述文字摘要，不描述图片）。

### 6.4 多周期回顾与图表输出（P1 组成部分，market 级）

**周期口径**：按交易日计——近5日=5、近10日=10、近1个月=22、近3个月=66 交易日。数据全部来自本地快照库（250 日回填正好覆盖 66 日需求），**零新增网络请求**。

**每个周期输出**（确定性规则生成，无 AI）：

| 字段 | 说明 |
|---|---|
| 起止日期 | 窗口首末交易日 |
| 均值 / 中位数 / 最低 / 最高 | 极值附发生日期 |
| 当前值窗口内分位 | 当前恐慌指数在此周期序列中的百分位 |
| 趋势判断 | 固定规则：当前值 − 窗口首值 ≥ +8 →「恐慌加深」；≤ −8 →「恐慌缓和」；否则「震荡」 |
| 样本标注 | 快照不足时如实标注（如「样本 40/66，部分日期为固定阈值口径」），不伪造历史 |

**REPL 文字输出**：Rich 摘要表（周期/区间/均值/极值/分位/趋势六列）+ 底部模板化人话总结（如「恐慌指数 63.4，较近5日均值上升 5.1 点，处于近三个月 82% 分位——市场情绪向恐慌方向加深」。模板填数，非 AI，保持零污染）。

**图片输出**（matplotlib，新增依赖）：

- 一张全景图：近 66 交易日总分走势折线 + 五档横向色带背景（极度贪婪红→极度恐慌蓝，20/40/60/80 档位横虚线）+ 四个周期窗口分界竖线；标题/轴/注释全中文。
- 保存路径：`~/.muyun/fear_index/charts/fear_market_{YYYYMMDD}.png`（当日重跑覆盖）；REPL 打印绝对路径（满足「用户可感知」铁律）。
- 中文字体降级链：Microsoft YaHei → SimHei → 英文标签兜底（实施时实测验证）。
- `--no-chart` 只出文字；`fear history` 默认两者都出。

**边界说明（诚实声明）**：多周期序列 P1 仅 market 级。L1/L2 的聚合总分真实历史只能从快照库积累日起算（快照类成分不可回填），P2/P3 上线时板块/个股的周期序列起点=快照积累起点，输出中如实标注，不回填伪造。

**依赖变更**：`pyproject.toml` 新增 `matplotlib`（uv add 一行；pillow 12.2.0 已在环境）。

### 6.5 P1 实施细则（自查定稿补充，2026-09-13）

**回填拆两层**（避免首次使用卡 REPL 5-8 分钟）：

- **轻量自动回填**：指数日线/两市成交额/两融余额/10Y国债/股息率——这些源「一次请求拿整段历史」，首次运行 `fear` 自动执行（几秒级），用户无感。
- **涨停池显式回填**：`stock_zt_pool_em/dtgc/zbgc` 按历史日期逐日拉（250 日 × 3 池 ≈ 750 请求，节流 0.4s → 约 5-8 分钟），走独立命令 `fear backfill --days 250`，Rich 进度条 + **断点续传**（已落盘日期自动跳过，中断重跑不浪费）。未回填前打板成分自动降级 threshold 口径并标注。

**两市成交额历史口径**：回填序列 = 上证指数日线成交额 + 深证综指日线成交额（`index_zh_a_hist` 两根线相加），与当日实时口径（新浪快照求和）存在小幅口径差，快照库中**分源标记**（`live` / `hist_index_sum`），分位计算混用时在输出标注。

**P1 未上线 scope 的诚实提示**：`fear 600519` / `fear 半导体` 在 P1 返回明确提示「个股/板块下钻在后续阶段上线，当前仅支持全市场」，不返回半成品数据。

**版本与缓存**：`FEAR_CACHE_VERSION` 常量置于 `fear_index/__init__.py`；快照文件带版本字段，版本不符自动视为无效重建；改成分口径必须 bump。

**实施期口径变更记录（2026-09-13 探针后定稿）**：
1. 股债性价比由「股息率−10Y」改为「自算日频盈利收益率−10Y」——乐咕 `stock_a_gxl_lg` 参数不含"沪深300"、`stock_index_pe_lg`/`stock_a_ttm_lyr`/中证 csindex 接口实测均为稀疏采样（近3年 38-40 个点或仅近20日），无法支撑 250 日分位窗；自算口径：乐咕 PE 采样点反推盈利阶梯（盈利=季度级慢变量，point-in-time），除以 baostock 日频收盘价，减 CalendarClient 10Y。价格端日频真实、盈利端阶梯化，无插值污染。
2. 两市成交额历史由东财 `index_zh_a_hist` 改为 **baostock**（东财指数接口实测 ConnectionError），上证综指+深证综指 amount 相加，口径不变。
3. 两市融资余额历史改用 `macro_china_market_margin_sh/sz`（一次请求整段历史，实测沪 3993 行/深 3795 行），替代逐日拉取。
4. 乐咕 `stock_market_activity_legu` 实测被反爬（NoneType.text），弃源，广度成分无双源交叉验证（诚实标注）。
5. 期权 `option_current_em` 实测无参签名，PCR 数据结构待 P2 探针。
6. **涨停池历史接口保留期实测仅约 20-30 个交易日**（更早日期一律空数据）——250 日回填目标调整为"回填到接口保留边界 + 每日快照积累"；打板成分 min_samples 特例放宽到 15（其余成分仍 60），分位窗随积累自动扩展到 250 日。

## 七、可扩展性：加一个新指标只需三步

1. 在 `metrics/` 对应 scope 文件里写一个函数 `(scope_ctx) -> MetricValue{raw, source, ts, status}`；
2. 在 `configs/fear_index.yaml`（或注册表默认值）登记：名称/适用 scope/权重/归一化方式/参数；
3. bump `FEAR_CACHE_VERSION`。

聚合器自动按「适用 scope ∩ 数据可用」选择成分——**指标之间零耦合，scope 与指标解耦**，未来加"期权 PCR""连板梯队"或"美股联动恐慌"都是纯增量。

## 九、风险与开放决策点

| # | 决策点 | 备选 | 建议 |
|---|---|---|---|
| 1 | **P1 范围** | a) 只 L0；b) L0+L1 一次做；c) 全量 L0-L2 | a——L0 先跑通验证口径与数据质量，L1/L2 复用同一引擎，边际成本低 |
| 2 | **AI 参与** | a) 纯客观+AI 仅解读；b) AI 参与加权 | a（"无污染"的根本保障） |
| 3 | **命令名** | `fear` / `panic` / `qz`（恐慌）/ `sentiment` | `fear`（直觉、无歧义） |
| 4 | **回填深度** | 60 日（快） / 250 日（分位更真，涨停池 250 次请求约 5-8 分钟一次性） | 250 日，放首次运行后台任务 |
| 5 | **期权 PCR** | v1 探针后收编 / v3 | 探针通过即 P2 收编 |
| 6 | **东财接口依赖** | 涨停池/板块指数均来自东财（反爬风险） | 沿用 net_guard 注册新源节流+熔断；板块指数备选 THS 版接口 |
| 7 | **matplotlib 新增依赖** | 引入绘图库会增加安装体积；极简环境可能失败 | uv 管理标准依赖链，风险低；`fear history --no-chart` 保证图表不可用时文字功能完整可用 |

**已知风险**：① 新浪全市场快照约 4 秒延迟+页面接口性质，广度成分盘中 TTL 10 分钟足够但非 tick 级；② 东财涨停池历史接口一次回填 250 天有被限流风险（节流+断点续传设计）；③ L1 板块成分接口（THS）已知可能超时，已有 fallback 链；④ "恐慌指数"首个版本的档位阈值（20/40/60/80）是先验设定，积累 60 日快照后应复核分位分布再校准——**版本内会输出样本数，透明可查**。
