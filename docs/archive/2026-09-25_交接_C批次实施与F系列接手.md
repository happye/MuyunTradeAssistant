## 三、监督体系与教训（接手者必读，别重踩）

本会话用「进度对齐监督员（全程）+ code-quality-guard（每批）」双监督，抓出的问题模式：

1. **回调插桩无时序测试 = 不可见 no-op**（P1）：ba 的 `batch_task_start` 放在 `auto_score_batch` 之后，回调 mark 全落空但全量全绿。修法见 `tests/benzong/test_ba_task_ledger_timing.py`（时序锁：fake 依赖函数触发一次回调即断言副作用已发生）。→ LRN-20260925-016
2. **假时序锁**：fake 返回非空 ranked 时，循环后回填会救活断言——锁形同虚设。fake 必须返回空集，让断言的唯一来源是回调。
3. **commit message 声称的落账与 diff 不一致**（两次）：plan/README 条目漏加。收尾时对照 `git show --stat` 逐文件点名核对。
4. **测试数字漂移**（四次：787→789→801→806→+24 算术错）：每批收尾统一重算 README/AGENTS 计数。
5. **monkeypatch by-value 捕获**：patch 模块属性期间的首次 import 会把替身永久捕获进导入方命名空间（ui 先于 chat 收集时 5 个桥测试全挂）。→ LRN-20260925-015
6. **subprocess `text=True` 必须显式 `encoding="utf-8"`**：中文 Windows 父进程按 GBK 解码 → 中文断言全灭。→ LRN-20260924-014
