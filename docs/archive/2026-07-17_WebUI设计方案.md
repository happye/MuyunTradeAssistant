# Web UI 设计方案（flask + Jinja2 + Tailwind + htmx）

> 日期：2026-07-17
> 栈：flask（后端）+ Jinja2（模板）+ Tailwind CSS（样式）+ htmx（交互）
> 性质：深入设计文档，**不推送**，审过后再说
> 关联：弃 textual TUI（4233867 本地保留不推），引擎解耦（chat/tools.py）复用

---

## 0. 设计目标

优雅 = **美观 web**（浏览器+Tailwind，>>终端）+ **流畅交互**（htmx 局部刷新，不整页跳转）+ **接住结果**（scan->选股->分析->加仓->回测 串联）+ **可维护**（轻量栈，无 JS 框架，用户可学）+ **复用引擎**（不重构 chat/tools.py）

解决你之前的痛点：单线滚动（web 多面板）、不接住（htmx 串联）、没快捷（按钮/点行）、终端怪（浏览器）。

---

## 1. 技术栈与理由

| 组件 | 作用 | 为什么选 |
|---|---|---|
| **flask** | 后端 web 框架，路由+API | 轻量、Python、复用引擎、生态成熟 |
| **Jinja2** | 模板引擎（Python 渲染 HTML）| flask 原生，片段渲染供 htmx 局部刷新 |
| **Tailwind CSS** | 样式框架 | 美观（卡片/表格/响应式），CDN 引入零配置 |
| **htmx** | HTML 属性实现 AJAX 交互 | **不用写 JS 框架**，HTML 属性（hx-post/hx-target）触发请求+局部刷新，用户可学 |

**不选**：React/Vue（前端工程化、构建、状态管理，你没经验维护门槛高）、streamlit（交互模型脚本重跑受限）、textual TUI（终端美观有限，已做 Phase1 弃）。

**诚实**：WebSearch 失效，flask/Tailwind/htmx 2026 现状基于训练知识（cutoff 2026-01），实施时验证 API（⚠️）。但这三个都是稳定老牌库，API 变化小。

---

## 2. 架构

```
浏览器（Tailwind CSS + htmx）
    ↕  htmx 请求（hx-post/hx-get）→ 返回 HTML 片段或 JSON
flask app（路由 + 模板渲染）
    ↕  调用（复用，不重构）
chat/tools.py（解耦层：init_engines + _orchestrator/_scanner_engine）
    ↕
底层引擎（Orchestrator/ScannerEngine/PortfolioManager/BacktestEngine/benzong）
```

**关键**：flask 不碰 CLI print 层，直接调 chat/tools.py 的引擎（已解耦返回结构化数据）。flask 路由调引擎拿数据 -> 渲染 Jinja2 片段或返 JSON -> htmx 局部更新 DOM。

## 3. 后端设计

### 3.1 路由（页面 + API）

| 方法 | 路径 | 作用 | 返回 |
|---|---|---|---|
| GET | `/` | 主界面 | Jinja2 index.html |
| POST | `/scan` | 触发扫描（后台线程）| task_id + 进度片段 |
| GET | `/scan/<task_id>` | 查扫描状态/结果（htmx 轮询）| scan_table 片段 或 进度片段 |
| POST | `/analyze/<code>` | 深度分析（后台线程）| task_id + 进度片段 |
| GET | `/analyze/<task_id>` | 分析状态/结果 | analysis_panel 片段 |
| POST | `/pos/add` | 加仓 | positions 片段 |
| GET | `/pos` | 持仓列表 | positions 片段 |
| POST | `/backtest/<code>` | 回测（后台线程）| task_id + 进度 |
| GET | `/backtest/<task_id>` | 回测结果 | 回测片段 |
| GET | `/last_scan` | 最近 scan（session_state.py）| scan 表片段 |
| GET | `/events` | 事件预警 | events 片段 |

### 3.2 长任务处理（关键，scan 4分钟/analyze 30-60s）

flask 默认同步阻塞，长任务会卡请求。方案：

- **threading 后台跑**（轻量，不引入 celery/redis）
- 全局任务 dict：`{task_id: {status, result, progress, error}}`
- **htmx 轮询**：`hx-trigger="every 2s"` 轮询 `/scan/<task_id>`，返回进度片段；完成返回结果片段 + 停轮询（`hx-swap` + 标记完成）
- 备选：SSE（Server-Sent Events）推送进度（htmx sse 扩展，更实时但稍复杂）-- Phase 2 优化

**推荐 threading + htmx 轮询**（简单，单用户本地够用）。

### 3.3 引擎调用

flask app 启动时调 `chat/tools.py` 的 `init_engines(config)`（一次），路由内用 `_orchestrator`/`_scanner_engine`（模块全局，已 init）。复用 tools.py 的引擎调用模式（analyze_stock/scan_market 已示范）。

## 4. 前端设计

### 4.1 主界面布局（index.html）

```
┌──────────────────────────────────────────────────┐
│ 顶栏：暮云思辨 | 大盘状态 | [扫描] 按钮           │
├──────────────┬───────────────────────────────────┤
│ scan 结果表   │ 分析栏（选中股深度分析）           │
│ # 代码 名称 涨│ ┌─────────────────────────────┐  │
│ 1 600519 茅台│ │ 贵州茅台 (600519)            │  │
│ 2 002230 讯飞│ │ 价:1800 涨跌:+2.5%           │  │
│ 3 ...        │ │ 市场:bullish 决策:BUY 评分:82│  │
│ ↑↓/点击选股   │ │ 仓位动作:试探建仓            │  │
│              │ │ 技术指标: MA5/MA20/MACD/RSI  │  │
│              │ │ 信号: 趋势↑ 量能↑ 情绪↑      │  │
│              │ │ [加仓] [回测] [加自选]       │  │
│              │ └─────────────────────────────┘  │
├──────────────┴───────────────────────────────────┤
│ 持仓概览：持仓列表 | 浮盈 | 快捷操作              │
└──────────────────────────────────────────────────┘
```

- Tailwind grid/flex 响应式（左 scan 表 1/3 + 右分析栏 2/3 + 底持仓栏）
- htmx：点 scan 表行 -> `hx-post="/analyze/<code>" hx-target="#analysis-panel"` 局部刷新分析栏

### 4.2 模板结构

```
templates/
  base.html              # 布局 + Tailwind CDN + htmx CDN + 导航
  index.html             # 主界面（继承 base）
  fragments/             # htmx 局部刷新片段
    scan_table.html      # scan 表片段
    analysis_panel.html  # 分析栏片段
    positions.html       # 持仓片段
    progress.html        # 进度片段（轮询时显示）
    backtest_result.html # 回测结果片段
```

- base.html：`<head>` 引 Tailwind CDN + htmx CDN，`<body>` 有 `{% block content %}`
- 片段：Jinja2 渲染局部 HTML，htmx `hx-swap="innerHTML"` 替换目标区域

### 4.3 htmx 交互示例

scan 表行选股：
```html
<tr hx-post="/analyze/600519" hx-target="#analysis-panel" hx-swap="innerHTML">
  <td>1</td><td>600519</td><td>贵州茅台</td>...
</tr>
```
点行 -> POST /analyze/600519 -> 返回 analysis_panel.html 片段 -> 替换 #analysis-panel。**不整页刷新**。

扫描按钮 + 进度轮询：
```html
<button hx-post="/scan" hx-target="#scan-table" hx-swap="innerHTML">扫描</button>
<!-- 扫描中返回 progress 片段，含 hx-trigger="every 2s" 轮询 -->
```

## 5. 交互流（完整链路）

1. 点[扫描] -> htmx POST /scan -> flask 后台线程跑 quick_scan -> 返回 task_id + progress 片段
2. htmx 轮询 GET /scan/<task_id>（每2s）-> 显示"扫描中...（4分钟）"
3. 完成 -> 返回 scan_table.html 片段 -> htmx 替换 scan 表
4. 点表中行 -> htmx POST /analyze/<code> -> 后台线程 analyze -> task_id + 进度
5. htmx 轮询 GET /analyze/<task_id> -> 分析栏显示"分析中...（30-60s）"
6. 完成 -> 返回 analysis_panel.html 片段 -> 替换分析栏
7. 点[加仓] -> htmx POST /pos/add -> 返回 positions.html -> 刷新持仓栏
8. 点[回测] -> htmx POST /backtest/<code> -> 后台线程 -> 结果片段

**全程局部刷新**，不整页跳转（htmx 优势，解决"单线滚动"）。

## 5.5 工具联动编排与数据互通（核心设计维度）

你重视所有工具的联动/编排/数据互通--这是 web UI 的核心价值（不止美观，更是工具协同）。深入设计：

### 现有工具清单（输入/输出/数据）

| 工具 | 输入 | 输出 | 核心数据 |
|---|---|---|---|
| scan | 规则/主题 | candidates[] | code/name/price/技术面 |
| 实时分析 | code | decision_result+stock_data | 决策/技术指标/信号 |
| 评分(bz) | code | BenzhongScore | 6维评分/等级/mode |
| 回测 | code+区间 | 回测结果 | 收益/交易/基准 |
| 持仓(pos) | code+价格+仓位 | positions[] | 持仓/TradePlan/生命周期 |
| events | - | 事件列表 | 事件/四要素 |
| 板块/新闻 | 关键词/code | 板块/新闻 | 成员/标题 |

### 联动链路（持仓生命周期）

工具不是孤岛，是持仓生命周期的环节：
```
选股(scan) -> 分析 -> 评分 -> 决策(加仓/观望)
  -> 持仓(pos add) -> 监控(持仓+events+评分更新)
  -> 调仓(回测验证+评分变化) -> 退出(pos rm/止损)
```

工具间数据流（自动传，不重输）：
- scan candidates -> 分析/评分（选中股自动传 code + stock_data）
- 分析 decision_result -> 持仓决策（决策驱动加仓按钮）
- 评分 BenzhongScore -> mode（气宗/剑宗）-> 持仓纪律
- 持仓 positions -> 回测/监控/评分更新（持仓股自动喂给）
- 回测结果 -> 策略验证 -> 反馈调参

### 编排工作流（一键组合多工具）

不止单工具操作，编排多工具工作流：

1. **选股工作流**：scan + 评分 TopN + 回测验证 -> 一键跑完，TopN 对比表（评分 vs 回测收益）
2. **持仓监控工作流**：持仓 + 评分更新 + events + 回测 -> 一键体检持仓
3. **调仓工作流**：评分变化 + 回测验证 + 加仓/减仓建议

工作流 = 工具编排 + 数据自动传 + 结果汇总。

### 数据互通（统一数据模型，不重复拉/输）

| 数据模型 | 共享工具 | 说明 |
|---|---|---|
| StockData（code/name/price/技术指标）| scan/分析/评分/回测 | 同股数据一次拉，工具复用 |
| candidates（scan 结果）| 分析/评分/加仓 | scan 结果存 session_state，工具引用 |
| positions（持仓）| 回测/监控/评分更新 | 持仓共享 |
| TradePlan（持仓计划）| 监控/调仓 | 计划共享 |
| session_state（last_scan/last_result）| 跨工具/跨会话 | 持久化 |

**实现**：flask session + session_state.py（已做）+ htmx `hx-include` 自动传选中 code/数据。

### UI 呈现（联动编排可视化）

- **工具联动**：点 scan 行 -> 按钮区"分析/评分/加仓/回测"（数据自动传 code，不重输）
- **编排工作流**：工作流面板（一键跑选股/监控/调仓，结果汇总）
- **数据互通**：选中股/持仓数据工具间自动传，前端显示"当前选中：XXX"
- **持仓生命周期视图**：选股->加仓->监控->退出 时间线 + 关键事件

## 13. 风险 / 诚实边界

- **flask 长任务阻塞**：threading 解决（不引入 celery/redis，单用户够用）
- **htmx 轮询频率**：每 2s，完成停（避免空轮询耗资源）
- **Tailwind CDN vs 本地**：CDN 简单（需联网），本地离线可用（Phase 2 优化，Tailwind CLI 生成）
- **session 跨请求**：flask secret_key 配置（app.py 设）
- **多用户并发**：单用户本地用，不考虑（任务 dict 全局，单用户 OK；多用户要隔离）
- **⚠️ WebSearch 失效**：flask/Tailwind/htmx 2026 现状训练知识，实施时验证 API（这三个稳定老牌，风险低）
- **Windows 防火墙**：flask 本地 localhost:5000，通常不拦
- **和 TUI 关系**：TUI 弃（不推），web 主推；REPL 保留作无 web 依赖 fallback
