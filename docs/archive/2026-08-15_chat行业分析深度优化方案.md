# chat 行业分析深度优化方案

> 日期：2026-08-15
> 触发：用户实测 chat 问"锂矿+持仓三阶段看法"，回答只基于产能泛泛而谈——**没结合需求端、供给端没细分、没挖掘上下游，毫无专业性**
> 关联：ISS-058（chat 修复）/ docs/2026-07-17_免费股票数据源调研.md / 记忆 `project_ai_ceiling`
> 性质：设计文档（先方案后实现，本方案未动代码）

## 0. 一句话定位

**这不是 prompt 写得好不好的问题，是数据供给缺口**：chat 现有 6 个工具全是技术面（analyze_stock/scan）/新闻（get_news）/策略知识（search_knowledge），**没有任何"行业基本面数据"工具**。模型答锂矿只能靠训练记忆+新闻标题，供需结构、商品价格、上下游图谱这些它拿不到——garbage in, garbage out（记忆 `project_ai_ceiling` 早有此判断，本方案是把它在 chat 层落地）。

## 1. 用户问题拆解（验收标准）

| # | 用户抱怨 | 数据层缺口 | 本方案补齐 |
|---|---------|-----------|-----------|
| 1 | 没结合需求端 | 新能源车销量/动力电池装机/储能装机等需求数据，零接入 | 需求数据组（akshare 月度数据，实测后定接口） |
| 2 | 供给端没细分 | 只有"产能"一词；无锂矿分来源（盐湖/锂辉石/锂云母）、无价格、无库存/仓单 | 商品价格组（期货/现货/仓单）+ 产业链图谱供给环节细分 |
| 3 | 没挖掘上下游 | 无产业链结构数据，模型不知道上游锂矿→中游锂盐/正极→下游电池/整车/储能的公司分布 | 产业链知识图谱（结构化 yaml）+ RAG 知识文件 |
| 4 | 毫无专业性 | 无供需平衡表框架、无周期位置判断依据 | prompt 输出框架 + 方法论知识文件进 RAG |

**验收标准（可验证）**：同一个问题（锂矿+持仓三阶段），新回答必须：(a) 引用真实价格/销量数据（带时间戳）；(b) 供给端分来源讨论（盐湖/锂辉石/锂云母各自的量价特征）；(c) 列出上下游环节及用户持仓在链条中的位置；(d) 用供需平衡框架给出周期位置判断；(e) 诚实标注拿不到的数据（如 SMM 周度库存）。

## 2. 架构设计

### 2.1 总览（加法，不动已跑通逻辑）

```
用户提问（行业类）
    │
    ▼
ChatAgent ──工具调用──▶ analyze_industry(industry)   ← 新工具
                            │
        ┌───────────────────┼─────────────────────────┐
        ▼                   ▼                          ▼
 产业链知识图谱         行业数据层                  RAG 知识库
 configs/industry_   src/data/industry_data.py  投资策略（持续更新）/
 chains.yaml         （价格/需求/仓单）         产业链方法论/*.md
（静态：环节-公司-     （动态：实时拉取，          （方法论：供需框架、
  关键变量映射）        30s超时降级）              周期判断）
```

- **静态知识**（产业链结构）用 yaml 图谱，不塞进 prompt（省 token、可维护、可复用给笨总景气度）
- **动态数据**（价格/需求/仓单）用数据层函数实时拉取，带超时降级（复用 `_get_stock_data_with_timeout` 的 daemon 线程模式）
- **方法论知识**（供需平衡表、周期分析框架）写成 .md 放进知识库 → 现有 RAG 自动索引（指纹变更自动重建，无需改 RAG 代码）

### 2.2 产业链知识图谱 `configs/industry_chains.yaml`（新文件）

结构设计（示例，锂电）：

```yaml
锂电:
  aliases: [锂矿, 碳酸锂, 锂盐, 锂电池, 动力电池, 新能源]
  上游:
    - 环节: 锂矿采选（盐湖提锂/锂辉石/锂云母）
      关键变量: 碳酸锂价格、产能投放节奏、矿石进口依赖度
      代表公司: [000792 盐湖股份(盐湖), 002460 赣锋锂业(锂辉石), 002192 融捷股份(锂云母), 002466 天齐锂业(锂辉石)]
    - 环节: 锂盐加工（碳酸锂/氢氧化锂）
      代表公司: [002460, 002466, 002240 盛新锂能, ...]
  中游:
    - 环节: 正极材料（磷酸铁锂/三元）
      关键变量: 加工费、产能利用率
      代表公司: [300750 宁德时代(自供), 002074 国轩高科, 300568 星源材质(隔膜), ...]
    - 环节: 电解液/隔膜/负极
      代表公司: [...]
  下游:
    - 环节: 电芯/电池
      代表公司: [300750 宁德时代, 002594 比亚迪, 300014 亿纬锂能, ...]
    - 环节: 新能源车/储能终端
      代表公司: [002594 比亚迪, 601633 长城汽车, ...]
  需求驱动: [新能源车月度销量, 动力电池装机量, 储能装机量]
  供给驱动: [碳酸锂价格, 锂矿产能扩张, 期货仓单]
  周期位置判断锚点: [碳酸锂价格相对历史区间分位, 供给增速 vs 需求增速, 库存/仓单趋势]
  分析要点:
    - 锂矿是典型周期品：价格中枢决定全链条利润分配
    - 供给刚性：锂矿产能投放周期 3-5 年，价格信号滞后
    - 下游景气传导：终端销量 → 电池排产 → 正极 → 锂盐 → 锂矿（滞后 2-3 季度）
```

Phase 1 建 5-6 条高频链：锂电、光伏、半导体、AI算力、煤炭/黄金（按用户持仓与常用主题定）。图谱的"代表公司"同时服务于：用户持仓在链条中的定位（第 3 个抱怨的直接解药）。

### 2.3 行业数据层 `src/data/industry_data.py`（新文件）

三组函数，全部带超时降级（daemon 线程 + join(25s)，复用 `_get_stock_data_with_timeout` 模式）、失败返回 `[工具失败]` 标记（ISS-059 语义，失败不占轮次、可重试）：

```python
get_commodity_price(commodity: str) -> str
# 锂电链路实测：futures_zh_daily_sina("LC0") 日线→近90日区间/当前分位
# + futures_spot_price(vars_list=["LC"]) 现货/主力/基差
# + futures_inventory_em("碳酸锂") 仓单趋势（库存代理）
get_industry_demand(industry: str) -> str
# car_market_fuel_cpca 新能源渗透率 + car_market_man_rank_cpca 头部厂商月销
# + macro_china_society_electricity 用电量；动力电池/储能装机 = 标注缺口
get_industry_supply_proxy(industry: str) -> str
# 仓单 + 产能扩张公告(新闻检索) + 成分股资本开支(Phase 2 baostock query_growth_data)
```

每项输出带**数据日期**（防把旧数据当新数据）。数据源映射表见 §3（2026-08-15 live-probe 实测，含三个接口坑：新浪期货 market 必须 "CF"、`stock_zygc_em` 必须带 SZ/SH 前缀、PMI/PPI 表倒序 head 最新）。

### 2.4 新 chat 工具 `analyze_industry`（tools.py + prompts.py）

```python
TOOL: analyze_industry(industry: str)
# 组装管线：图谱(静态) + 价格/需求/仓单(动态) → 拼接成 ≤3500 字结构化报告
# 内部顺序：图谱匹配（别名模糊）→ 价格 → 需求 → 供给代理 → 降级（某项失败标注[数据缺失]而非整体失败）
```

工具结果结构（给模型看的"行业数据包"）：

```
【产业链结构】锂电：上游(锂矿采选/锂盐加工)→中游(正极/电解液/隔膜)→下游(电池/整车/储能)
  - 各环节代表公司列表（含用户持仓所在环节标注）
【价格数据】碳酸锂期货主力 xx 元/吨（2026-08-14），近90日区间 xx~xx，当前分位 xx%
  现货 xx 元/吨（2026-08-14）；仓单 xx 万吨（环比 xx）
【需求数据】新能源车 xx 月销量 xx 万辆（同比 xx%）；动力电池装机 xx GWh（同比 xx%）
【供给观察】产能投放线索（新闻）：...；[SMM周度产量/库存：付费墙，无免费接口，标注]
【数据缺口】明确列出本轮拿不到的数据
```

### 2.6 prompt 升级（CHAT_SYSTEM_PROMPT）

增加：
- **工具使用指南**：用户问行业/板块前景、供需、周期 → 必须先调 `analyze_industry` 再回答
- **行业回答强制框架**：三阶段（当下/未来数月/更长远）× 供需两端分开 × 上下游分层 × 周期位置判断（数据支撑，禁止泛泛而谈）
- **诚实规则**：数据缺口必须明说（"SMM 库存数据无免费接口，用仓单代理"），禁止用模糊语言掩盖无数据
- 用户持仓股 → 标注其在链条中的环节位置（上游承压/下游受益等）

## 5. 验证方案

1. **单测**：数据层 mock（接口失败/超时/空数据三态）；图谱匹配（别名/模糊）；工具降级路径（ISS-059 失败语义复用）
2. **真实提问对比**：修复前 vs 修复后，同一个锂矿三阶段问题，逐条对照 §1 验收标准
3. **数据新鲜度打印**：工具结果必须带数据日期，抽查与公开数据一致
4. **落盘**：分析类回答存 `分析报告/chat_*.md`（顺带消化交接文档待办 #2，可选）

## 6. 诚实边界（必须写进方案，防止假装覆盖）

1. **SMM/百川的周度产量、库存、开工率 = 付费墙**，免费源拿不到 → 用期货仓单+公告新闻做代理，工具输出必须标注"代理指标"
2. **月度需求数据滞后**：中汽协/电池联盟数据次月发布，回答须标注数据截至月份
3. **产业链图谱是静态人工知识**：新建/维护需人工；初期只建高频链，冷门行业降级为"仅价格+新闻"模式
4. **机构一致预期接口（东财）有反爬风险**：失败降级，不阻塞
5. 本方案**不保证"预测准确"**——它保证"AI 基于真实结构数据推理，而非空谈"；推理质量仍取决于模型

## 7. 红线（沿用 7-17 调研报告 §6）

1. 不改笨总 `effective_grade` 公式；Phase 3 联动必须配回测 + bump `CACHE_VERSION`
2. chat 工具是**加法**：analyze_stock/scan_market 等已跑通逻辑一行不动
3. 防矫枉过正：数据接不进来就降级标注，不要为了"全"去碰反爬灰色源
4. 所有新接口走 daemon 超时模式，不许挂起 chat
