## H01 🔴 涨跌停一刀切：创业板/科创板正常大涨大跌被误封

**位置**：`src/core/execution_layer.py:132-149`

```python
# 保守判断：涨幅>9.5%视为涨停 —— 无视板块差异
return data.change_pct >= 9.5
```

**实测复现**：
```python
300502（创业板，20cm 板）当日 change_pct=+12% → evaluate(OPEN)  → blocked=True「涨停封板，无法买入」
300502 当日 change_pct=-12% → evaluate(CLOSE_ALL) → blocked=True「跌停封板，无法卖出」
```
创业板/科创板每日 ±20% 空间，**9.5%~19.9% 的单日波动完全合法且常见**（尤其 2026 批次3 全是 300/688 标的）。后果：
1. **回测**：强趋势日建仓被静默封锁（`blocked_no_open_price` 之外的另一类错过）、止损日卖出被吞成 HOLD_POSITION——对高波动板块的回测收益与风控双双失真
2. **实盘**：被建议"今日无法买入"（其实能买）

**修法建议**：按代码前缀分板判定（成本小，~10 行 + 回归）：
```python
@staticmethod
def _limit_up_threshold(stock_code: str) -> float:
    c = str(stock_code)
    if c.startswith(("30", "68")):  return 19.5   # 创业板/科创板 20cm
    if c.startswith(("83", "87", "88", "92", "43", "4")): return 29.5  # 北交所 30cm
    return 9.5                                    # 主板/暂无ST数据（ST±5% 判不到，维持原简化并注释声明）
```
**属回测行为改动**（放行此前被误封的交易）→ 修复后需 A/B 对照（批次3 全 300/688，预计影响最直接）。

## H03 🟠 RAG 索引三文件非原子 + load 无一致性校验

**位置**：`src/rag/store.py:139-197`（save 顺序写 index.faiss/docs.json/config.json；load 不读 config.json、不校验数量一致）

**实测复现**：构造 docs=2 与 index.ntotal=3 的错配目录 → `load()` 返回 **True**（无告警）→ 查询 top3 只返回 2 条（`idx < len(self._docs)` 静默过滤掉超界向量）。反向错配（docs 多于 index）时 `_id_to_idx` 会把 id 映射到**错误的向量位置** → 检索内容张冠李戴。

**触发**：重建索引时 `save()` 写到一半崩溃/断电/磁盘满。概率低但一旦发生 RAG 静默降智（检索结果缺失或错配），且 `verify` 手段缺失（用户只感觉"检索不准"）。

**修法建议**（成本小）：
1. `load()` 增加校验：`self._index.ntotal != len(self._docs)` → 返回 False（触发下次全量重建）
2. `save()` 改 tmp+`os.replace`（G01/B24 同款原子写），三文件顺序：先 docs.json/config.json 后 index.faiss（load 以 index 为准做校验）

## H02 ⚪ trailing 止损的入场价反推链脆弱

**位置**：`src/core/trade_plan/adjuster.py:78-81`

```python
entry = plan.locked_initial_stop / 0.92        # 假设止损=entry×0.92（实际通常是 2×ATR，此路几乎必错）
if plan.when_sell_targets:
    entry = plan.when_sell_targets[0] / 1.10   # 假设 tier1=+10%（用户改过分档即失真）
```

根因：**TradePlan 没有 entry_price 字段**，下游（adjuster trailing 的 5% 浮盈门槛）只能反推。用户把止盈分档改成 +15%/+30% 后，反推 entry 偏大 36% → `gain_pct` 被低估 → trailing 迟迟不触发（止损上移建议失效）。

**修法建议**：TradePlan 加 `entry_price: Optional[float]`（旧文件缺省 None 走现兜底，向后兼容）；`generate_plan_draft` 直接填真值；adjuster 优先用它。成本小（schema 兼容性需回归往返测试，可顺带锁 G01 同款原子写）。属依赖 schema 的低优先改进，可与 G01 同批。
