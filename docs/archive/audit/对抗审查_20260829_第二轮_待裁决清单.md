## 一、🔴 致命（P0）

### B01 技能引擎：`require: majority` 阈值 off-by-one，2-3 条条件的规则实际等于 `any` **[本人复核]**
- **证据**：`src/core/skill_engine.py:715`
  ```python
  result["met"] = conditions_met >= max(1, total_conditions // 2)
  ```
  2 条条件 → `2//2=1` → 满足 1 条即触发；3 条条件 → `3//2=1` → **满足 1 条即触发**。多数决应为 `//2 + 1`。
- **触发面**：全库 14 个技能 YAML（约 100+ 条规则）**只有 `oversold_confirm.yaml` 的 3 条显式写了 `require: all`**，其余全部走默认 `majority`（`:115` `require=rule.get("require","majority")`）。
- **影响**：**整个决策链第一层的"多条件确认"形同虚设**——设计意图"3 个条件里至少 2 个成立"实际变成"任 1 个成立即出信号"。这会系统性放大信号数量、稀释置信度，且完全静默（无任何日志）。
- **修法**：改 `max(1, total_conditions // 2 + 1)`（或 `math.ceil(total/2)`）。
- **成本**：1 行。**但会改变所有历史决策与回测结果，属策略改动，需重跑基线。**

  `kdj_k_above_20`、`kdj_k_above_50`、`kdj_k_below_80`（kdj.yaml）
  `rsi_12_above_50`、`rsi_12_below_50`、`rsi_24_above_50`、`rsi_24_below_50`、`rsi_6_above_30`、`rsi_6_below_70`（rsi.yaml）
- **最坏后果不是"不触发"，而是降档触发**：以 `rsi.yaml:35-43` RSI 多头排列（BUY / conf 0.75 / weight 1.0）为例，规则写的是 RSI-6 **且** 12 **且** 24 中至少 2 个 >50；因 12/24 两个条件被丢弃，分母变成 1，配合 B01 的 `//2` → **只要 RSI-6 > 50 就发 BUY 信号**。空头排列（SELL）同理。

- **修法**：补注册这 9 个条件（多数可复用已有 `rsi_6_above_50`/`kdj_k_above_80` 的实现）；并建议把 `logger.debug` 升为 `warning`，否则下次新增条件拼错仍然静默。

### B03 笨总：**一票否决（红线）后总分与等级完全不受影响 —— 红线股照样评 A 级** **[审查员验证]**
