## 4. 执行顺序与每卡硬约束（细节以任务卡原文为准）

1. **L0 观察协议真正按合同消费**（G6，先做）：同一资格函数决定字段缺口/diagnostic/effective/报告分母；同一规范语义对象生成去重指纹；版本升独立新协议（旧 v6 不追认）。字段来源必须真实：行情时点来自实际行情及缓存元数据、证据截止来自被消费快照、rule version 来自真实规则版本——**不能把 now 填进几个字段凑形式完整**。两臂（legacy/fusion）分别保存 action/target 权重（KNOWN/UNKNOWN/NOT_APPLICABLE）/blockers/执行与版本；MID/LONG 分别评资格。V1/V2 转绿；未来时点/错版本降级；WRITE 失败不算观察。行情时点不可得时先交保守降级，不承诺有效样本已开始。
2. **L1 数量账户读取资格贯穿消费者**（G1/G5，可与 L0 分开但共享接线串行）：quantity 决定有无仓、批次决定成本/可卖、估值与 NAV 决定权重资格——ratio_stale/quantity_fact 必须有真实消费者。**现有 float 不得以 None 击穿也不能用 0 假装未知**；在应用装配边界处理未知权重（quantity>0 决定有仓；无合格估值抑制精确新增，但不吞硬风险/退出意图）；重建仓已持股不能因旧比例 0 漏建议。RATIO_ONLY 老账户分开适配，迁移不反造历史。V3 两场景转绿；跨入口相同账户版本相同事实。
3. **L2 检查点公开入口可建立可复核**（G2/G3，L0 未完成时纵向测试预期 diagnostic——**不得为绿跳字段门**）：用户能查看稳定证据 ID、把条件绑定到合格材料、显式确认风险；同一命令重放不换掉原引用；未给引用列可选证据和缺口，错主体/未核验/不支持条件的引用拒绝；不得把导入的全部 claims 自动绑定任意条件。验收实走真实入口全链 + 缺引用/伪引用/缺原件/未确认风险/重启/变更未接受反例；**单独断言命题/计划/报告状态，不用 observation_kind=effective 掩盖 UNESTABLISHED**。跨界替身只用于数据/存储隔离，不能 mock 掉实际待验环节。
