## 三、问题明细（含修复建议，待裁决）

### 🔴 P1-A：TF-IDF 降级路径，进程重启后首次检索必崩
- **现象**：sentence-transformers 不可用的环境（降级 TF-IDF）中，服务重启→加载旧索引→第一次语义检索抛 FAISS 维度异常，RAG 整体不可用。
- **根因**：`TFIDFEmbedder` 的 vectorizer 词汇表**只在内存**（`embedding.py:287-294` fit 于建索引进程），不随索引持久化；重启后 `embed_query`（`:308-316`）对未 fit 的 vectorizer 用**查询文本现场 fit** → 维度=查询词数≠索引维度。
- **放大器**：`service.py:202-215` `_is_index_embedder_compatible` 只比较 provider/model 字符串（tfidf==tfidf 通过）→ 旧索引照常加载，把错误延迟到查询期才爆。
- **实证**：同一语料，建索引维度 19，重启后 embed_query 维度 4，FAISS 直接抛维度断言。
- **修复建议（三选一，改动都不大）**：① `_is_index_embedder_compatible` 对 tfidf provider 恒返 False（TF-IDF 索引不缓存，每次重建——最简单，符合降级定位）；② 把 vectorizer vocabulary 存进 index_dir 并在 load 后 restore；③ embed_query 未 fit 时抛明确 RuntimeError 触发上层重建。推荐 ①。
- **附带**：`service.py:164-173` 降级只发生在"初始化时模型加载失败"；运行期 encode 抛错无兜底，可顺手在 retrieve 层加 try→返回空结果（fail-open 与现状一致，防 chat 崩）。

### 🔴 P1-B：质量评估基线 100% 失效（仪表盘坏了）
- **现象**：重跑 `tests/rag_eval/evaluator.py`，30 条查询 Recall@5/MRR/NDCG **全部 0.000**。
- **根因**：`relevance_labels.json` 标注挂在**旧 doc_id 体系**（`ch54_p5`/`望周知—系统化交易大纲_p6` 等），v0.8.8.8 系列隔离后新 id 为 `rz54_p5` 等 → `evaluator.py:123` `q_labels.get(doc.id, 0)` 全部落 0。实测标注 **0/150 命中**当前索引。
- **叠加缺陷（P2-D）**：`auto_label`（`evaluator.py:75-109`）用**被测系统自己的** embedder 算余弦打标——自我循环验证，即使迁移了 id，指标也系统性虚高；且 auto_label 用 `embed()` 而非 `embed_query()`（无 BGE 前缀），标注与线上检索不同分布。
- **历史基线**：eval_report.json（已恢复）avg_recall@5=0.8 / MRR=0.733 / NDCG@5=0.749——该数字基于旧 id 体系+自我标注，参考价值存疑。
- **修复建议**：① 用当前 id 体系重跑 auto_label 先恢复可用性；② 中期改为「检索结果人工快审」或用更强模型（bge-reranker/LLM judge）独立打标；③ evaluator 加 labels 兼容性自检（命中率<50% 时拒绝出报告，防假告警）。

### 🟡 P2-A：chunk_overlap=50 收了但从未使用（死参数）
- **根因**：`ingestion.py:249` 签名收参 → `:269-311` 函数体零引用；`_split_by_sentences`（`:314-350`）同样无重叠逻辑。`service.py:72` 从 settings 读入后传进 `load_strategy_files`（`:356`）被静默吞掉。
- **实证**：同文本 overlap=0 与 overlap=50 输出逐元素相等（A/B 一致）。
- **影响**：相邻块零重叠，跨块边界的语义（一句被切断的话）两边都只剩半截，检索两头都吃亏。docstring 还声称"300-800 字"与实际 500/1.5x 不符（文档漂移）。
- **修复建议**：在 `_split_by_sentences` 组块时携带前块尾部 overlap 字符；**注意改分块必须全量重建索引**（fingerprint 会自动触发）+ rag_eval 重评。

### 🟡 P2-B：49 块（6.9%）超 512 token，bge 静默截断
- **数据**：708 块中 >500 字 49 块（最长 **2831 字**，来自长段落合刊），401-500 字 490 块。bge-small-zh max_seq_length=512 token，中文≈1 字 1 token，>500 字块尾部必然被 sentence-transformers 截掉。
- **影响**：长块尾部内容对语义检索"不存在"，但 BM25 仍可召回 → 两路信号打架。
- **修复建议**：与 P2-A 同一刀口——分块时按 token 上限（≈480 字安全线）硬切，或把 `_split_into_chunks` 的 1.5x 溢出容忍（`:295`）收紧为按 chunk_size 严格切。需重建索引。

### 🟡 P2-C：jieba 零自定义词典
- **实证**：全 src grep `load_userdict|add_word|suggest_freq` 零命中。
- **影响**：A 股黑话（打板/低吸/气宗/剑宗/笨总/超景气）被切碎，BM25 关键词路召回受损；语义路可部分兜底。
- **修复建议**：`知识目录/` 加 userdict.txt（几十个领域词即可），KeywordRetriever 与 TFIDFEmbedder 的 tokenize 前统一 `jieba.load_userdict`。改动小、无索引重建（BM25 词表随 index_documents 重建，TF-IDF 词表需重建注意与 P1-A 联动）。

### 🟢 P3 项（择要）
- **P3-A faiss 中文绝对路径**：`faiss.read_index(中文绝对路径)` 实证 ENOENT（C++ fopen 按 ANSI 代码页解析 UTF-8 中文）；当前 `settings.yaml` 用相对路径 `./knowledge/index` 规避。**建议在 AGENTS.md 踩坑区记一条：index_dir 必须保持相对路径或 ASCII 路径**，否则表现为"每次启动都全量重建索引"。
- **P3-B 模型代际**：bge-small-zh-v1.5 为 2023 年模型（C-MTEB 平均分较 base/large 低 5-6 点；bge-m3 支持 8k 上下文+稠密+稀疏混合检索）。升级收益：召回质量+消灭 P2-B 截断问题；代价：模型体积/内存/首次重建时间。**建议列入待办非紧急**。
- **P3-C reranker 缺失**：检索精度上限受截断质量限制；加 bge-reranker-base 对 top20 交叉重排是标准增强，CPU 推理 20 条≈秒级可接受。
- **P3-D 增量/规模**：146 文件指纹变化→全量重建（bge CPU 约 1-2 分钟），当前可接受；BM25 纯 Python 全库打分，万块级需换 rank_bm25/倒排。
