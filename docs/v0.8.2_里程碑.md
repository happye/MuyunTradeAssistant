## Phase 2：分层回测模式 + 中间决策日志 ✅

### 已完成

1. 三层回测模式已可运行：`decision_only`、`decision_strategy`、`decision_strategy_execution`。
2. CLI 已支持 `--layer-mode` 切换。
3. 回测结果已记录 `diagnostics.daily_decisions` 与 `diagnostics.execution_logs`。
4. 导出表已优先使用真实日志而不是仅靠事后字符串推断。
5. 已支持 `--export-layer-comparison-json` 单次导出三层对照 JSON。
6. 已实现逐日 `merged_timeline`：三层 `daily_decisions` + `execution_logs` 按信号日期对齐，形成统一逐日对照视图。
7. 已实现层间分歧自动分类：`none` / `strategy_modified` / `execution_blocked` / `strategy_and_execution`。
8. 已支持 `--export-layer-comparison-txt` 导出人类可读的三层对照分析报告。
9. 对照文本报告包含：层级汇总表、层间差异、分析提示、逐日分歧统计、分歧逐日明细。

### 已落地能力

1. 单次命令即可产出三层对照导出（JSON + TXT），并能稳定区分信号层、策略层、执行层责任。
2. merged timeline 提供逐日三层数据对齐，自动标记层间分歧类型与发生频率。
3. 分歧明细可精确定位"哪天、哪层、如何修改"（如策略层将 ADD 改为 HOLD_POSITION）。
4. 对照 JSON 的 `merged_timeline.divergence_summary` 可直接用于 AI 归因分析。

注：基础文本化对照报告已具备，当前缺的是更细粒度的 merged timeline 与更正式的 analyzer 结构。

1. 已新增 `src/core/backtest_validator.py`，形成独立验证模块。
2. CLI 已支持 `--export-validation-json` / `--export-validation-txt`。

5. 已支持样本内 / 样本外拆分和 walk-forward 窗口验证。
6. 已支持多标的批量验证模板：可批量运行多只股票并导出统一验证汇总。
7. 已支持按趋势 / 震荡 / 极端行情分桶的验证报告。

### 当前缺口

1. 还没有更贴近实盘链路的实时一致性扩展。

### 当前状态

1. Phase 3 当前只保留已完成基线，不再作为主开发面继续扩展。

## Phase 4 进度

1. 已开始在分析导出和诊断链路中输出 `action_semantic`。
2. 已完成首个规则拆分闭环：`SELL` 不再默认全部走 `REDUCE`，已支持空仓卖出留在 `STAY_OUT`、止盈减仓、强卖压退出、强止损清仓。
3. 已把止盈 / 止损阈值收口为统一规则，并新增结构化 `sell_path` 字段用于区分 `flat_sell / stop_loss_trim / stop_loss_exit / take_profit_trim / trend_exit / weak_sell`。
4. 已开始把这些语义接入非回测链路：普通 CLI 展示、聊天格式化、持仓更新建议与持仓记录持久化均可观察到 `action_semantic` / `sell_path`。
5. 已补齐 `sell_path` 在无 `diagnostics` 导出路径下的 fallback 推断，分析主表不再默认回落为 `None`。
6. 已收紧 `trend_exit` 判定：不再仅凭高卖压直接清仓，而是要求同时出现均线失守、趋势走坏或持仓已进入退出生命周期等事实条件，未破位的强卖压回落到 `weak_sell`。
7. 已把趋势退出理由文本同步到策略层导出链路，并修复 `EXIT/STOP` 语义边界：`trend_exit` 理由即使包含“跌破”类趋势破坏描述，也不会再被共享语义推断误判为 `STOP`；同时新增 reporter fallback 直跑回归脚本锁定 `trend_exit / weak_sell / take_profit / stop_loss`。
8. 已补齐分析导出 summary 的交易语义统计口径，统一输出 `action_semantic_breakdown` 与 `sell_path_breakdown`，并修复 reporter fallback 在 `TradeRecord`/`dict` 两种路径下的兼容性。
9. 已把减仓保护期接回新的 `sell_path` 语义：`take_profit_trim / weak_sell / stop_loss_trim` 不再共用同一固定保护窗口，而是按减仓原因分别记录 `last_reduce_reason` 与保护期天数，减少减仓后立刻回补的循环交易。
10. 已在保护期内阻断“同一减仓原因重复执行”：相同 `sell_path` 的连续 `REDUCE` 不再日复一日重复触发，不同减仓原因仍可继续执行，开始把止盈/弱卖/浅层止损的频率控制真正落到行为层。
11. 已进一步收紧 `trend_exit` 边界：`EXIT` 生命周期本身不再直接等价于趋势破坏或清仓依据，只有新的趋势破坏事实出现时才会从减仓升级到清仓，避免此前战术减仓在后续被误放大为 `CLOSE_ALL`。
12. 已把战术减仓的生命周期语义收口到 `HOLD`：`take_profit_trim / weak_sell / stop_loss_trim` 不再把持仓推进到 `EXIT`，旧 `EXIT` 状态下继续减仓时也会回到 `HOLD`，避免生命周期继续误导后续卖出判定。
13. 已明确 `take_profit_trim` 与 `trend_exit` 的优先级：盈利中的新趋势破坏不再被优先解释成战术止盈，出现新的趋势破坏事实时会直接进入 `trend_exit`，避免把该退出的场景继续保留为分批减仓。
14. 已把 `stop_loss_trim` 与 `trend_exit` 从同一分支里拆开：出现浅层止损信号时，如果同时有新的趋势破坏事实，不再被默认压回止损减仓，而是允许直接进入 `trend_exit`，避免“趋势结束卖点”继续被止损减仓吞掉。
15. 已移除策略层里残留的 `LOW_POSITION_CLEAR -> CLOSE_ALL` 旧兜底：小仓位下的 `take_profit_trim / stop_loss_trim / weak_sell` 不再被统一升级成清仓，保留原始卖出语义。
16. Phase 4 验收已完成：六条卖出路径均有正例与反例覆盖，策略层回归与 reporter fallback 回归通过，窄回测链路通过，里程碑状态已与代码状态同步。

## Phase 4 明确完成计划

当前状态：已完成。

1. 剩余目标只围绕六条卖出路径：`flat_sell / stop_loss_trim / stop_loss_exit / take_profit_trim / trend_exit / weak_sell`。
2. 每条路径都必须同时有正例和反例边界：不仅要证明“该触发时能触发”，还要证明“不会误判成相邻路径”。
3. 必须清掉所有旧泛化兜底：`REDUCE -> EXIT`、`lifecycle == EXIT -> CLOSE_ALL`、所有减仓共用一个固定保护窗口等旧逻辑都不能残留。
4. Phase 4 只允许两类配套工作：必要回归测试和必要导出/展示同步；不再继续自然扩张到新的统计面板、解释层或 Phase 5 机制。
5. 剩余执行顺序固定为：
	- 先补 `take_profit_trim / stop_loss_trim / weak_sell / trend_exit` 的最后一轮反例边界
	- 再确认没有残留旧兜底逻辑
	- 再跑 `tests/test_strategy_layer_sell_split.py`、`tests/test_backtest_reporter_sell_path_fallback.py` 和一条窄回测链路
	- 满足验收标准后直接将 Phase 4 标记完成，不再继续向外生长
6. Phase 4 完成验收标准：
	- 六条卖出路径都有正例测试
	- 六条卖出路径至少各有一个反例测试
	- 两条聚焦回归脚本通过
	- 一条窄回测链路通过
	- 里程碑状态与代码状态一致

## Phase 5 交付结果

1. 已引入显式最短持有窗口：新开仓后使用 `min_hold_remaining` 阻断 `weak_sell / take_profit_trim / stop_loss_trim` 这类战术性卖出，减少刚建仓就被噪音洗掉。
2. 已引入显式加仓保护窗口：加仓后使用 `add_protection_remaining` 阻断立即反向减仓，减少加仓后第二天又撤回的循环交易。
3. 已把“正常波动”与“趋势破坏”拆开：`trend_exit` 只在新的趋势破坏事实出现时触发，不再拿生命周期状态或泛化卖压直接替代。
4. 已把策略语义接入非回测链路：普通 CLI、聊天格式化、持仓持久化、回测 `TradeRecord`、reporter summary 与 fallback 均以 `action_semantic` / `sell_path` 为主。
5. 已完成验收闭环：策略层卖出语义拆分回归、reporter fallback 回归、组合窗口恢复与手工 `--pos-add` 补录窗口生效均已覆盖。

3. 保持日线只负责具体触发，不让上位周期直接替代触发层。
