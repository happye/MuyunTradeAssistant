- 日期：2026-09-11

- 口径：全部数据由 `pytest --collect-only` / `-rs` / 磁盘 walk **实测**得出，非目测；盘点脚本用后即删。

## 一、先回答：4 个跳过分别是什么

`pytest tests/ -rs` 的权威输出（不是读代码猜的）：

| # | 位置 | 原因（pytest 原文） | 类别 |
|---|------|---------------------|------|
| 1 | `tests/core/test_tech_context_e2e.py:127` | 脚本式E2E需真实AI+argparse参数，用 uv run python 直跑（设MUYUN_E2E_AI=1强制pytest跑） | **设计性跳过** |
| 2 | `tests/core/test_tech_context_e2e.py:181` | 同上（同一文件的第 2 个用例） | **设计性跳过** |
| 3 | `tests/data_sources/conftest.py:38` | 全市场 0 只 (sina外源间歇456反爬/东财断连,非代码bug,重试可恢复) | **外源抖动** |
| 4 | `tests/data_sources/conftest.py:38` | 成交额获取失败 (依赖sina全市场快照,外源间歇,非代码bug) | **外源抖动** |

**2 个是故意的，2 个是网络的。**

- **设计性（2 个）**：`tests/core/test_tech_context_e2e.py:22` 有模块级
  `pytestmark = pytest.mark.skipif(os.environ.get("MUYUN_E2E_AI") != "1", ...)`。
  这个文件需要**真 AI key + argparse 参数**，在 pytest 下没有意义；想强制跑就 `MUYUN_E2E_AI=1`。
- **外源抖动（2 个）**：`tests/data_sources/conftest.py` 有一段 hook，把 `test_all_api` 这类"双协议"连通性用例的
  返回值 `(False, detail)` 按关键词分流——含「未配/未登录/**外源**/**间歇**」→ `pytest.skip`（**可见跳过**），
  其余 `(False, ...)` → `AssertionError`（真失败）。设计意图见文件 docstring：
  > 裸元组返回会被记成 pass-with-warning（假阴性——外源挂了/配置坏了也显示绿）

  所以这 2 个跳过是**"当前的 sina 全市场快照正被反爬"**这件事被诚实地暴露出来了，不是代码 bug。

> ⚠️ 由此引出一个基线问题：这 2 项会让"全量 passed/skipped"在 **626/2** 与 **624/4** 之间摆动。
> AGENTS.md 要求"每次全量的数字写进 commit message"，但基线里混着不可控的外源项 → 数字本身不可复现。

## 二、规模：628 个用例到底多不多

| 维度 | 数值 |
|---|---|
| `src/` .py 文件 / 行数 | 89 个 / **32,906 行** |
| `tests/` .py 文件 / 行数 | 89 个 / **14,146 行**（其中被 pytest 收集的 **79** 个） |
| 测试/源码 行数比 | **0.43** |
| 收集用例 | **628** 个 |

**结论：数量不算多，问题在组织。** 0.43 的测试源码比在工程实践里属于正常区间（0.5~1.5 常见），
628 个用例对 3.3 万行源码也不算失控。真正扎眼的有三点：

1. **`tests/core` 一个目录吃掉 48% 的用例**（303/628）；
2. **90 个 .py 里有 11 个根本不产生用例**，其中 9 个是一次性/半手工验证脚本被当成测试长期留着；
3. **文档表（AGENTS.md §tests）与实际目录对不上**，且是"账实同步"那次改错的。

## 四、分类质量评估

### ✅ 做得好的部分

- **目录按用途划分**（2026-08-17 commit `705df2c` 做的目录化），不是按文件类型堆一起；
- 根 `tests/conftest.py` 统一把项目根塞进 `sys.path`，脚本式测试目录化后共用入口；
- **每个测试文件都有中文 docstring 说明"锁死什么语义"**——这一条做得比多数项目好，
  审计时能直接看出意图（如 `test_h_block_fixes.py` 写明 H01/H02/H03/H05 各是什么）；
- **双模设计**（56 个文件既能 pytest 跑、也能 `python xxx.py` 直跑）让"回归测试"和"诊断工具"共用一份代码。

**P1-4　完全没有 pytest 配置**

`pytest.ini` / `pyproject.toml` / `setup.cfg` / `tox.ini` **全部不存在**。后果：

1. 全量命令必须每次手打 `--ignore=tests/artifacts --ignore=tests/rag_eval`，漏打则与文档口径不一致；
2. **没有任何 marker**（代码里只用了 `parametrize` 2 次、`asyncio` 4 次），无法 `-m "not external"` 做分层跑；
3. `pytest-asyncio`（1.4.0）靠默认严格模式工作，将来升级易碎；
4. 无 `testpaths`，新人直接 `pytest` 会扫到 `scripts/` 之外的意外目录。

## 五、建议方案（分两档，不动目录的那种优先）

### 档 A：最小改进（**推荐先做**，不挪任何文件，风险≈0）

1. **修 AGENTS.md tests 表**：删掉"tests/ui 已不存在"的错误结论、补 `tests/rag` 行、补 data_sources 的诚实跳过说明。
2. **新建 `pytest.ini`**（或 `pyproject.toml` 的 `[tool.pytest.ini_options]`）：
   ```ini
   [pytest]
   testpaths = tests
   addopts = --ignore=tests/artifacts --ignore=tests/rag_eval
   markers =
       external: 打真实第三方接口（sina/东财/akshare），结果受反爬影响，不计入提交基线
       ai: 需要真实 AI key
       slow: 单文件 > 30s
   ```
   收益：全量命令可以退化成一个 `pytest -m "not external"`，基线数字变可复现。
3. **给外源用例打 `@pytest.mark.external`**（`tests/data_sources/*` + 上述抖动的 2 个），
   让"提交基线"与"偶发外部抖动"分开。
4. **把 `scripts/verify_indicator_math.py` 纳入回归**：两种做法任选——
   (a) 加一个 `tests/core/test_indicator_math_script.py` 用 `subprocess` 调用它并断言退出码；
   (b) 把它改造成 pytest 文件（把内部断言暴露成 `test_*` 函数）再迁回 `tests/core/`。
   **推荐 (b)**，因为它本来就该是回归资产。
5. **清 3 个卫生问题**：`tests/backtest/_matrix_driver.py` 去硬编码路径或移出 tests/；
   6 个 `_*.json` 与 `_matrix_driver.py` 按约定从 git 移除（`git rm --cached`，保留在盘上）。

### 档 B：目录重构（**谨慎**，是 2026-08-17 目录化之后的第二次大搬迁）

```
tests/
├── conftest.py
├── unit/            # 纯 mock、无外源（chat/benzong 多数 + core 的纯逻辑用例）
├── integration/     # 跨模块 + mock 引擎（ui、chat_command_bridge、回测驱动）
├── contract/        # 锁语义类回归，按领域再分：
│   ├── indicators/  # 指标数学（含 verify_indicator_math）
│   ├── guards/      # PlanGuard / fundamental_alert / live 门控 / 回测隔离
│   └── review/      # D04 / E / G / H / ISS-078/082/089/090/091 统一命名
├── external/        # 打真外源（原 data_sources），marker 隔离
└── scripts/         # 0 用例的矩阵/探针（原 backtest 的 6 个 + _matrix_driver）
```

**代价评估**：目录一挪，AGENTS.md §tests 表、`docs/` 里所有 `tests/xxx.py` 引用、
`skills/muyun-agent-tutor/SKILL.md` 的行号台账、`.learnings/` 里的路径全部要同步；
按本项目"账实漂移"的复发频率，**收益（可读性）大概率不抵风险（大批文档引用失效）**。
所以我建议：**先做档 A，档 B 等某次大版本重构窗口再一起做。**

## 六、一句话结论

- **4 个跳过 = 2 个故意（E2E 需真 AI）+ 2 个外源反爬**，都是"诚实跳过"而非掩盖失败。
- **628 用例 / 0.43 测试源码比不算多**；真问题是 `tests/core` 占 48% 成为杂物桶、三套命名体系、
  无 pytest 配置、文档表写错、以及**指标数学验证器已掉出回归覆盖**。
- 最该立刻补的一条：**`scripts/verify_indicator_math.py` 重新纳入回归**（它是 C 区块两条高判反率 bug 的唯一数学证明）。
