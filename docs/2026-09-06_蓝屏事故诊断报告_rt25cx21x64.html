⚡ 大概率原因裁定（一句话版）

你机器上的 Realtek RTL8125 2.5G 有线网卡驱动（rt25cx21x64.sys）存在缺陷，在系统高负载/功耗波动时抛出未处理异常触发蓝屏——这是驱动层问题，不是 CPU 缩肛，也不是我之前说的"内存耗尽"（该定论不成立，正式收回：内存耗尽只会卡顿、杀进程，根本不会蓝屏；蓝屏是内核驱动的锅）。

你补充的第二个终止代码 KMODE_EXCEPTION_NOT_HANDLED (0x1E) 进一步强化诊断：0x1E 与 0x7E 同属"内核异常未处理"家族（官方文档：0x1E 最常见异常码 = 0xC0000005 内存访问违规，元凶排行第一位的就是网络适配器驱动）。同一驱动在不同时机炸出不同异常码，正是竞态类驱动 bug 的典型指纹；两次代码都不是 CPU 缩肛的特征（0x124 WHEA / CLOCK_WATCHDOG_TIMEOUT 均未出现）。

我的改动（双模型加载+多个后台验证进程）扮演的角色是触发器：CPU 满载 → 整机功耗/PCIe 链路波动 → 网卡驱动竞态 bug 被引爆。雷是驱动的，扳机有一部分是我按的。

补充：第二个终止代码 KMODE_EXCEPTION_NOT_HANDLED (0x1E) 怎么解读

问题解读
0x1E 和 0x7E 什么关系？同属"内核异常未处理"家族。微软官方文档：0x1E = 内核模式程序产生异常处理器未捕获，最常见异常码就是 0xC0000005（内存访问违规）；官方处置指引："如果在蓝屏消息中点名了驱动，禁用该驱动或找厂商要更新"。0x7E 是系统线程版本的同类异常。
两次不同代码矛盾吗？不矛盾，反而是驱动竞态 bug 的典型指纹。同一个有缺陷的驱动，在不同时机/不同内核路径下炸出不同异常码（0x7E/0x1E/0x3B 常见混发），官方文档与多个技术来源均确认"网络适配器驱动"排在 0x1E 元凶第一位。
0x1E 那次画面上有没有"失败的操作: xxx.sys"？已确认：没有其他字样。这符合预期——0x1E 经常不点名文件（微软文档明确此时需靠 dump 分析定位），不影响主诊断：0x7E 那次已点名 rt25cx21x64.sys，同一驱动缺陷在不同时机表现为两种代码。
触发条件是否锁定？已锁定。你实测确认：只有继续执行跑模型类高负载任务时才触发，日常使用从不蓝屏，三次全部命中重负载窗口，时间相关性100%。→ 诊断定稿：触发条件=高负载，直接原因=RTL8125 网卡驱动缺陷。
0x1E 的第二嫌疑人（内存条）要排除吗？暂不需要立刻动。理由：内存故障的蓝屏时机是随机的，而你这三次精确绑定"跑模型"（高负载），时间相关性强烈指向负载触发的驱动缺陷。但若更新网卡驱动后仍蓝屏，MemTest86 过夜测试立即升级为必做项。

修复方案（按优先级，等你审核后执行）

  1. 方案一（治本，强烈推荐）：更新 Realtek 2.5G 网卡驱动
    ① 打开华硕官网支持页 → 输入你的主板型号 → 驱动下载 → 分类选 LAN / 网络
    ② 下载最新的 Realtek 2.5G Ethernet 驱动（你现在的版本是 2024-09 的 1125.021.0903.2024，找更新的）
    ③ 设备管理器 → 网络适配器 → Realtek Gaming 2.5GbE Family Controller → 右键卸载设备 → 勾选"尝试删除此设备的驱动程序" → 不重启
    ④ 安装刚下载的新驱动 → 重启
    微软社区同款案例的官方建议路径；不推荐鲁大师/驱动精灵类第三方工具。
  2. 方案二（缓解，10 分钟立即可做，可与方案一叠加）
    ① 设备管理器 → 网卡属性 → 电源管理 → 取消勾选"允许计算机关闭此设备以节约电源"
    ② 同窗口 高级 选项卡 → 关闭 节能以太网 (EEE / Green Ethernet)、绿色以太网类选项
    ③ （案例提及的冲突源）若装有游戏加速器/网络过滤类软件，考虑卸载——你的代理客户端（127.0.0.1:7890）一般不至于蓝屏，先不动，驱动更新无效再排查
  3. 方案三（保险，针对 CPU 担忧）：XTU 限频
    按你自己的计划用 Intel XTU 限制最大频率（如 P 核限 4.8-5.2GHz）+ 关闭主板自动超频——作为整机稳定性保险合理，但请记住它不解决本次蓝屏，失败模块是网卡驱动。
  4. 验证与兜底（可选但建议）：确认元凶 + 排除内存
    ① 看 dump：管理员 PowerShell 跑 Get-ChildItem C:\Windows\Minidump | Sort LastWriteTime -Desc，然后用免费工具 BlueScreenView（NirSoft）打开 dump，看 "Caused By Driver" 一列——若都是 rt25cx21x64.sys 结论锁死
    ② 兜底排除内存：若更新网卡驱动后仍蓝屏，立即用 MemTest86（U 盘启动）过夜测试——0x1E 的第二嫌疑人是 RAM 故障，驱动更新无效时它升级为必做项
    ③ XTU 限频：按你原计划作为整机保险上（若 CPU 确有缩缸史），它降低重负载压力间接减少触发，但治不了本次的驱动病根
