# 行业景气度客观数据源——细致评估（2026-08-24）

> 触发：用户要求"先做细致评估，再决定做不做"（待办清单 #6）。
> 结论先行：**技术可行、积木已有一半，但影响面是全评分体系（所有股票的分数和 mode 分配），
> 且 13 链之外行业仍有数据墙。建议不立即全量接入，走"分链灰度+回测门"路线，由用户决定是否立项。**

---

## 一、问题本质（要解决什么）

笨总评分有一条硬闸门：`effective_grade()` 里行业景气度 ≤30 → 最高 C、≤50 → 最高 B、≤0 → 直接 F。
这条闸门的输入 `industry_prosperity` 维度目前**只喂给 AI "行业名 + 30 天新闻标题（≤10条）"**，
纯主观判断——闸门立在最软的柱子上（ISS-055 定性）。AI 判错景气 → 全维度分数失真 + mode 错配。

换更强的模型没用（ISS-047 已澄清：garbage in garbage out，是数据供给问题不是智商问题）。

## 二、已有积木盘点（比想象中多）

chat 行业分析层（ISS-061，2026-08 落地）已经建好了可复用的客观基础：

| 积木 | 内容 | 状态 |
|------|------|------|
| 商品价格锚 | 13 条链：生猪 LH/钢铁 RB/铜 CU/碳酸锂 LC/多晶硅 PS/工业硅 SI/黄金 AU/煤炭/玻璃纯碱/造纸/橡胶/油脂饲料/化肥 | ✅ 实测可用，90日/250日分位算法现成 |
| 现货基差 | 生意社现货-期货对照 | ✅ 实测可用 |
| 库存 | 期货仓单近30日变化（累库/去库） | ✅ 实测可用（交割库口径） |
| 需求月度数据 | 乘联会 NEV 渗透率/产量、国家能源局用电量、统计局 PMI/PPI | ✅ 实测可用 |
| 行业→商品映射 | `configs/industry_chains*.yaml` 图谱 + AI 自举沉淀 | ✅ 手写6链+自举持续扩 |
| **景气度维度 prompt** | benzong dimensions 里 industry_prosperity 的 AI 提示词 | ⬜ 待接线 |

**缺口**：13 链之外的行业（软件/医药/军工/白酒等无商品锚的行业）仍无免费客观源——数据墙残留，
这部分只能继续靠新闻标题或维持现状。

## 三、接入方案设计（两个层级）

### 方案 A：prompt 注入（轻，推荐起步）
把该股所属行业的客观摘要（商品价格分位/基差方向/仓单趋势/需求同比）拼进 industry_prosperity
维度的 prompt，让 AI 在硬数据背景下打分。**不改公式、不改闸门逻辑**。
- 改动面：dimensions/industry_prosperity.py 一处 + 数据适配层复用 industry_data
- 影响：AI 判断有据可依；但仍是 AI 主观最终判定，闸门可靠性提升有限

### 方案 B：客观信号直接参与闸门（重，治本）
对有商品锚的行业，用规则直接生成景气度参考带（如：价格3年分位<20% 且 去库 → 景气度下限保护；
价格90%分位以上 + 累库 → 上限压制），AI 分数被客观带夹逼。
- 改动面：评分公式层 + CACHE_VERSION bump + **全量回测验证（红线）**
- 影响：闸门真正站上硬数据；但规则阈值本身需要校准（每个商品周期特性不同），工作量数倍于 A

## 四、风险与代价清单

1. **改评分 = 动全体系**：任何接入方式都改变部分股票的分数 → mode 分配变化 → 必须三批回测把关
   （M-A 同款验证流程，现成）
2. **CACHE_VERSION 必须 bump**：同股同日旧缓存全部失效，首次跑 bz scan 会整批重新计费（AI 调用量×N）
3. **覆盖面不均**：只有 13 链内行业受益，会造成"链内链外评分口径不一致"的新问题（需在展示层标注数据来源差异）
4. **数据源脆弱性继承**：akshare 接口的坑（列名漂移/反爬）会传导进评分主链路——台账纪律需升级为评分级监控
5. **维护成本**：每条链的商品映射需要人工确认，自举图谱未经复核不能直接进评分

## 五、建议路线（若立项）

```
第1步 方案A灰度：只接锂电/煤炭/生猪 3 条最成熟链，prompt 注入，观察 2-4 周
      验证：bz <链内股> vs <链外同类股> 的景气度稳定性对比 + 三批回测不恶化
第2步 评估后决定是否扩到 13 链
第3步 方案B（客观夹逼）仅对数据最硬的 2-3 个品种试点，单独回测验证阈值
```

  M-A 刚修完 mode 层，连续动两处底层不利于归因；建议至少等 M-A 复跑结论稳定后再叠加变更
